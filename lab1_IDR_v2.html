🏛️ SOC FOUNDATIONS

What is a Security Operations Center (SOC)?

A Security Operations Center (SOC) is a centralized function within an organization responsible for monitoring, detecting, analyzing, and responding to cyber threats 24/7/365.

👁️
Continuous Visibility

Maintains real-time awareness over all endpoints, servers, network perimeters, and cloud identities across the enterprise infrastructure.

⚡
Rapid Threat Containment

Minimizes attacker dwell time (MTTD / MTTR) by detecting malicious activity early in the cyber kill chain and isolating compromised assets.

🛡️
Asset & Risk Defense

Protects critical intellectual property, customer data, and operational systems from disruption, exfiltration, and extortion (ransomware).

SOC Operational Postures
# A mature SOC operates continuously across two complementary postures: [REACTIVE POSTURE] Alert Ingestion → Triage & Verification → Threat Containment → Incident Remediation [PROACTIVE POSTURE] Threat Hunting → Detection Engineering → Vulnerability Management → System Hardening
🔄 OPERATIONAL LIFECYCLE

The Core Operational Cycle

The fundamental mission of every SOC follows a continuous, iterative 4-stage lifecycle:

STAGE 01 1. MONITOR Continuous ingestion of telemetry across endpoints, network traffic, authentications, and web services.
→
STAGE 02 2. DETECT Rule correlation, threat intelligence matching, and anomaly engines flagging suspicious activity.
→
STAGE 03 3. ANALYZE Analyst investigation: validating alerts, establishing blast radius, root cause, and timeline reconstruction.
→
STAGE 04 4. RESPOND Containing compromised hosts, revoking stolen credentials, blocking malicious IPs, and system recovery.
🔁 The Crucial Feedback Loop (Detection Engineering) Continuous Improvement

Every resolved incident feeds directly back into Step 1 & 2: writing new SIEM correlation rules, deploying custom Sysmon/EDR blocks, and tuning out false positives so the defense posture becomes harder to penetrate over time.

📊 ORGANIZATIONAL STRUCTURE

SOC Roles & Tier Escalation Model

To handle thousands of daily alerts without burning out analysts, modern SOCs employ a structured tier system:

TIER 1 · TRIAGE
Alert Analyst

Role: Monitors the SIEM console 24/7.
Primary Task: Rapidly triage alerts, filter out False Positives, gather initial context, and escalate validated threats within 15 minutes.

TIER 2 · HANDLER
Incident Responder

Role: Deep-dive investigation.
Primary Task: Scopes the breach extent, reconstructs the attacker timeline, isolates infected hosts, revokes access, and coordinates eradication.

TIER 3 · HUNTER
Threat Hunter / Sr.

Role: Proactive defense & engineering.
Primary Task: Assumes the network is already breached; hunts for stealthy APT activity, crafts detection rules, and evaluates advanced TTPs.

LEADERSHIP
SOC Manager

Role: Operations & Governance.
Primary Task: Oversees personnel, manages tool licensing and budget, reports breach status to C-suite/legal, and tracks performance metrics (MTTD/MTTR).

Escalation Lifecycle in Practice
# Realistic Alert Flow: SIEM Alert Fires → Tier 1: Confirms malicious base64 PowerShell → Escalates to Tier 2: Isolates host & cleans malware → Tier 3: Hunts across all 5,000 endpoints for identical parent processes!
🔒 SECURITY PRINCIPLES

How a SOC Defends the CIA Triad

Every security control, log search, and incident response action exists to safeguard one or more core tenets of information security:

🔐
Confidentiality
Preventing Disclosure

Threats: Data exfiltration, credential harvesting, insider leaks.
SOC Defense: DLP alerts, monitoring unusual outbound bandwidth, detecting unauthorized access to HR/finance databases.

🛡️
Integrity
Preventing Alteration

Threats: Unauthorized file tampering, registry modification, log deletion.
SOC Defense: File Integrity Monitoring (FIM), Sysmon Event 11 (FileCreate), Event 1102 (Log Clearance Alert).

⚡
Availability
Ensuring Authorized Access

Threats: DDoS floods, Ransomware encryption, service termination.
SOC Defense: Network traffic thresholds, WAF rate limiting, early detection of mass file renaming/encryption processes.

Real-World Scenario: Double Extortion Ransomware

Attackers first exfiltrate confidential customer records (violating Confidentiality), then encrypt virtual machines to shut down production (destroying Availability), and threaten to publish modified fake records if uncooperative (threatening Integrity). The SOC must defend all three simultaneously!

👁️ PHILOSOPHY OF DEFENSE

The Visibility Imperative: Why We Need Events

“You cannot defend what you cannot see, and you cannot investigate what was never recorded.”

In enterprise defense, ground truth does not come from assumptions — it comes strictly from timestamped telemetry. When an incident occurs, every analyst must answer the 6 Forensic Questions:

1. WHO?

Which user account, security identifier (SID), or service principal initiated the action? Was it elevated?

2. WHAT?

What exact action occurred? Was a process executed? A user created? A sensitive file read or copied?

3. WHEN?

Precise UTC timestamp. Establishing a reliable chronological sequence of events is the cornerstone of forensics.

4. WHERE?

Which source machine, internal IP, external destination IP, or cloud tenant hosted the event?

5. HOW?

What mechanism was used? Which parent process spawned the command? What protocol or port was targeted?

6. OUTCOME?

Did the attempt succeed or fail? (e.g. HTTP 200 vs 403; Windows 4624 success vs 4625 bad password).

🔍 CORE TERMINOLOGY

Log vs Event vs Alert vs Incident

Defenders must never confuse these terms. They represent four distinct phases of information distillation:

1. RAW LOG
Millions / day
The immutable, timestamped record written to disk by an OS, device, or app documenting an activity (e.g. text file or EVTX).
2. EVENT
Thousands / day
An observable occurrence within an IT environment that holds potential security significance (e.g., successful user logon, firewall block).
3. ALERT
Dozens / day
A high-priority notification triggered when one or more events match a specific detection rule or anomaly threshold (requires analyst review).
4. INCIDENT
Few / month
A verified breach or critical security violation confirmed by human investigation that requires immediate formal containment and eradication.
Concrete Example Walkthrough
# Real-World Progression: • Raw Log: Single Windows Security record generated: "EventCode=4625, User=admin, Status=0xC000006D" • Event: "A failed logon attempt occurred on Domain Controller from workstation IP 10.0.0.55" • Alert: SIEM rule triggers: "High-Volume Brute Force Detected: 200 failed logons in 60 seconds followed by success!" • Incident: Analyst validates admin account compromise + lateral movement: P1 Critical Incident declared!
⚖️ DETECTION METRICS

The Triage Truth Matrix: Evaluating Detections

Whenever an alert fires (or fails to fire), it falls into one of four statistical quadrants:

Quadrant Alert Fired? Actually Malicious? Operational Impact & Action
TRUE POSITIVE (TP) YES (Alert) YES (Attack) Success! Threat detected. Escalate immediately to Tier 2 for containment.
FALSE POSITIVE (FP) YES (Alert) NO (Benign) Alert Fatigue. Benign backup script flagged as ransomware. Requires rule tuning.
TRUE NEGATIVE (TN) NO (Quiet) NO (Benign) Normal Operations. Regular employee traffic correctly ignored by detection rules.
FALSE NEGATIVE (FN) NO (Quiet) YES (Attack) The Worst Nightmare! Stealthy adversary penetrated network undetected. Blind spot!
SOC Analyst's Golden Rule for Tuning

Every SOC must continuously tune rules to minimize False Positives (which burn out analysts) without opening blind spots that produce False Negatives (which let attackers breach undetected).

🧬 LOG ANATOMY

Anatomy of a Log Entry: Raw vs Structured

Every well-formed security log contains specific forensic fields, regardless of the operating system:

Traditional Raw Text Log (Unstructured)
# Apache Access Log (Combined Log Format): 192.168.1.105 - john [20/Oct/2026:14:22:10 +0000] "GET /api/v1/user?id=1 HTTP/1.1" 200 4523 "https://example.com" "Mozilla/5.0 Windows NT 10.0" # Linux Auth Log: Oct 20 03:15:22 srv01 sshd[12345]: Failed password for root from 185.220.101.42 port 52431 ssh2
Modern Normalized Log (JSON / Key-Value)
{ "@timestamp": "2026-10-20T03:15:22.412Z", "host.name": "srv01", "event.action": "logon-failed", "source.ip": "185.220.101.42", "source.port": 52431, "user.name": "root", "process.name": "sshd", "event.outcome": "failure" }
1. Timestamp

Must be ISO 8601 UTC standard for chronological correlation.

2. Subject & Identity

User account, Domain, Security ID (SID), or Service Account.

3. Object & Action

Target file, registry key, process image, or network socket.

4. Status & Outcome

Success vs Failure code (e.g. Windows 0xC000006D, HTTP 403).

🌐 TELEMETRY SOURCES

Enterprise Log Landscape: Where Logs Originate

Modern security operations ingests telemetry from across five fundamental infrastructure tiers:

1. Host & Endpoint Layer Highest Volume

Windows Event Logs (.evtx), Sysmon kernel events, Linux authentication/syslog (`/var/log`), macOS unified logging, EDR telemetry.

2. Network & Perimeter Layer Traffic Visibility

Next-Gen Firewalls (Palo Alto, Fortinet), IDS/IPS alerts (Snort, Suricata), DNS query logs, NetFlow/IPFIX, VPN concentrators, Proxy logs.

3. Web & Application Layer App Defense

Web servers (Nginx, Apache, IIS access/error logs), Web Application Firewalls (WAF), database query logs (SQL audit), custom business app logs.

4. Identity & Cloud Services Layer Access & SaaS

Active Directory Domain Services, Microsoft Entra ID (Azure AD), Okta, M365 Unified Audit Log (UAL), AWS CloudTrail, GCP Audit Logs.

The Core Defense Insight

An attacker rarely attacks one layer alone. They probe the perimeter (Network), exploit a vulnerability (Web), execute code (Host), and escalate privileges (Identity). To catch them, we must monitor all layers simultaneously!

🪟 ENDPOINT TELEMETRY

Windows Event Logging Architecture (.evtx)

Windows stores event logs in binary XML files (`.evtx`) inside `C:\Windows\System32\winevt\Logs\`. The three primary core channels are Security, System, and Application.

Event ID Channel Event Description SOC Analyst Significance
4624 Security An account was successfully logged on Verifies legitimate access; inspect Logon Type (2=Console, 3=Network, 10=RDP).
4625 Security An account failed to log on Tracks password guessing, dictionary attacks, and Brute Force attempts.
4672 Security Special privileges assigned to new logon Administrator account logon; watch for unauthorized privilege utilization.
4688 Security A new process has been created Tracks malware execution; requires Command Line Auditing GPO enabled!
4720 / 4732 Security User account created / Added to Admin group Attacker establishing backdoor persistence and privilege escalation.
7045 System A new service was installed in the system Common persistence mechanism (MITRE ATT&CK T1543.003).
1102 / 104 Security / System The audit log was cleared High Severity! Anti-forensic wiping to conceal malicious footprint.
⚙️ ADVANCED TELEMETRY

Why Default Logs Aren't Enough: Enter Sysmon

Default Windows logs leave critical forensic blind spots. System Monitor (Sysmon) is a free Sysinternals kernel driver that records advanced threat telemetry directly into Windows Event Viewer:

Default Windows Blind Spots ❌
  • Does not calculate cryptographic hashes (SHA256) of launched executables.
  • Cannot tie network socket connections to the specific PID that initiated them.
  • No logging of DNS lookups performed by processes.
  • Fails to track process memory injection (`CreateRemoteThread`).
Sysmon Deep Telemetry Superpowers ✅
  • Automatic SHA256 / MD5 hashing of every running executable.
  • Full process ancestry (Parent CommandLine + Child CommandLine).
  • Logs all outbound network connections with PID and source/dest IPs.
  • Detects DLL hijacking, named pipe creation, and driver loading.
SYSMON EVENT 1
Process Creation

Full image path, CommandLine arguments, parent process, hashes, and user SID.

SYSMON EVENT 3
Network Connection

Ties network connections directly to the executable (e.g. `powershell.exe` calling external IP).

SYSMON EVENT 22
DNS Query

Logs domain name queries initiated per process; catches C2 domain lookups.

🐧 LINUX TELEMETRY

Linux Logging Architecture & Key Files

Linux systems historically manage logging through the Syslog daemon (`rsyslog`/`syslog-ng`) storing plain-text records in `/var/log/`, complemented by modern systemd-journald and auditd.

Authentication Logs Debian / RHEL

• Ubuntu / Debian: /var/log/auth.log
• RHEL / CentOS / Rocky: /var/log/secure
Records all SSH logins, sudo command executions, PAM authentications, and failed password attempts.

System & Kernel Messages OS Operations

• General Syslog: /var/log/syslog or /var/log/messages
• Kernel Ring Buffer: /var/log/dmesg
Tracks device drivers, hardware errors, system boot parameters, and service state changes.

Querying Linux Logs: Classic CLI vs Modern Journalctl
# 1. Searching failed SSH attempts in Debian/Ubuntu: sudo grep "Failed password" /var/log/auth.log | tail -n 5 # 2. Investigating sudo commands via systemd journal: sudo journalctl _COMM=sudo --since "1 hour ago" -n 10 # 3. Kernel audit logs (auditd) tracking file execution: sudo ausearch -m EXECVE -ts today

Network & Perimeter Telemetry

Demo 4: Spotting Attacks in Web Access Logs

Web application attacks leave unmistakable signatures in web server access logs. Let's dissect real attack payloads recorded in Apache/Nginx logs:

Sample Access Log Entries Under Attack
# 1. Normal legitimate web request: 10.0.0.12 - - [20/Oct/2026:10:00:01 +0000] "GET /products/item?id=45 HTTP/1.1" 200 3120 # 2. Attacker probes for SQL Injection (Note the single quote '): 198.51.100.4 - - [20/Oct/2026:10:00:15 +0000] "GET /products/item?id=45' HTTP/1.1" 500 842 # 3. Successful SQL Injection data extraction: 198.51.100.4 - - [20/Oct/2026:10:00:22 +0000] "GET /products/item?id=45%20UNION%20SELECT%20username,password%20FROM%20users-- HTTP/1.1" 200 58291 (Huge Response!) # 4. Directory Traversal / Local File Inclusion attempt: 198.51.100.4 - - [20/Oct/2026:10:00:45 +0000] "GET /view.php?file=../../../../etc/passwd HTTP/1.1" 403 420
SQL Injection Clues

Look for single quotes (' or %27), SQL keywords (UNION, SELECT), comment dashes (--), and abnormally large response byte sizes.

Path Traversal Clues

Look for repeated ../ dot-dot-slash patterns attempting to escape web root to read sensitive system files (/etc/passwd, win.ini).

Status Code Insights

A 500 Server Error reveals the database query crashed; an immediate subsequent 200 OK indicates the attacker successfully adjusted their syntax!

🏝️ ARCHITECTURAL CHALLENGE

The Centralization Dilemma: “Islands of Data”

In an enterprise with thousands of servers, leaving logs scattered across individual machines creates a catastrophic defensive failure:

⚡
1. Anti-Forensic Wiping

When an attacker gains Administrator or root privileges, their immediate priority is clearing local logs (wevtutil cl Security or rm -rf /var/log/*). If logs remain local, all evidence evaporates!

⏱️
2. Impossible Search Scale

An analyst cannot manually RDP or SSH into 5,000 distinct servers during an active breach to search for an IOC. Triage would take months instead of seconds.

🧩
3. Missing Correlation Context

A firewall block means nothing without seeing the host process; a workstation login failure means nothing without knowing the external VPN IP. Fragmented logs tell no coherent story.

⏰
4. Time Drift & Format Chaos

Without time synchronization and field normalization, piecing together a chronological timeline across Linux, Windows, Cisco, and AWS becomes virtually impossible.

🛡️ CENTRALIZATION SOLUTION

Centralization & The Critical Role of NTP

The solution is simple yet non-negotiable: ship all logs immediately to a centralized, tamper-proof repository (SIEM) the instant they are generated.

Why Centralization Solves the Problem
  • Write-Once, Tamper-Proof: Even if an attacker wipes the endpoint, the log was already shipped off-box and safely indexed in the SIEM!
  • Single Pane of Glass: Query millions of events across 10,000 hosts simultaneously in sub-second search times.
  • Multi-Source Correlation: Tie a firewall alert, an endpoint process, and a cloud login into a unified incident graph.
  • Regulatory Compliance: Fulfills PCI-DSS, ISO 27001, and SOC2 requirements for centralized audit trails.
The Non-Negotiable Foundation: NTP Time Sync

Network Time Protocol (NTP) synchronizes all enterprise clocks to within milliseconds of UTC (Coordinated Universal Time).

# Why Time Drift Destroys Investigations: Server A Clock: 10:04:00 (Off by +4 minutes) Firewall Clock: 10:00:00 (Correct UTC) Analyst sees a firewall drop at 10:00:00, but Server A's exploit log is stamped at 10:04:00. Automated correlation rules FAIL because the events appear 4 minutes apart!
🚚 DATA INGESTION

How Logs are Shipped: Agents vs Agentless

How does log telemetry physically travel from thousands of disparate endpoints into the central SIEM? Organizations leverage two primary architectures:

1. Agent-Based Ingestion Endpoints & Servers

A lightweight software service installed directly on the host (e.g., Splunk Universal Forwarder, Elastic Agent, Wazuh Agent, Winlogbeat).

  • Local Disk Buffering: If network drops, logs queue on disk and never get lost.
  • Data Compression & Encryption: Sends TLS encrypted, compressed streams.
  • Minimal Footprint: Uses <1% CPU and negligible memory.
2. Agentless Ingestion Appliances & Cloud

Used for network switches, firewalls, and cloud services where installing third-party agent software is impossible.

  • Syslog Forwarding: Devices push RFC 5424 syslog over UDP 514 or TCP/TLS 6514 to a central collector.
  • Windows Event Forwarding (WEF): Native Windows Kerberos push to a central Windows Event Collector (WEC).
  • Cloud REST APIs: SIEM pulls audit trails directly via API tokens (e.g. AWS CloudTrail, Microsoft Graph API).
⚙️ PROCESSING ENGINE

The 6-Stage SIEM Processing Pipeline

Before an alert ever appears on an analyst's monitor, raw telemetry passes through a rigorous 6-stage engineering pipeline:

01 COLLECT Agents, Syslog streams, and API integrations gathering raw bytes.
→
02 AGGREGATE Buffering incoming logs into high-throughput message queues (Kafka).
→
03 PARSE Normalizing raw text into Common Information Models (e.g. src_ip).
→
04 ENRICH Adding GeoIP location, Threat Intel reputation, and Asset Criticality.
→
05 INDEX Compressing and writing into high-speed searchable index clusters.
→
06 CORRELATE Multi-source logic matching detection rules → Alert Generated!
Stage 3 & 4 in Action: What Normalization & Enrichment Looks Like
# Raw Log: "Oct 20 14:02:11 gw-fw[52]: DROP src=198.51.100.4 dst=10.0.0.5 sport=52112 dport=22" # Normalized (CIM): action="blocked", src_ip="198.51.100.4", dest_port=22, app="ssh" # Enriched (ThreatIntel): src_ip_country="NL", threat_score="95/100 (Known Tor Exit Node)"

🧠 SIEM PLATFORMS

🔎
Search & Investigation

Dashboards & Metrics

💻 HOST DEFENSE

EDR & Sysmon: Endpoint Visibility & Active Response

While SIEM looks across the entire enterprise, Endpoint Detection and Response (EDR) provides micro-visibility and live surgical intervention directly inside host memory and processes:

Capability Traditional Antivirus (AV) Modern EDR (CrowdStrike, Defender, LimaCharlie)
Detection Model Static signatures and known file hashes. Behavioral AI, memory analysis, parentage anomaly tracking.
Fileless Malware Blind to scripts executing purely in RAM. Interprets AMSI telemetry, memory injection, reflective DLL loading.
Telemetry Recorded Only alerts when a known signature matches. Flight Recorder: Records every process, socket, and file touched.
Live Active Response Can only quarantine or delete a file. Remote Host Isolation, process kill, remote live terminal shell!

🛡️ NETWORK DEFENSE

Network Security: Firewalls, IDS/IPS & NSM

Network defenses operate at the wire level, monitoring packets as they traverse between security zones:

🧱
Firewalls & NGFW
Gatekeeper

Role: Enforces access control policies.
NGFW (Next-Gen): Inspects Layer 7 applications (e.g. blocks BitTorrent or Tor even if running over standard port 443).

🚨
IDS vs IPS
Detection vs Prevention

• IDS (Snort/Suricata): Sits out-of-band on a TAP/SPAN port. Passively alerts without interrupting traffic.
• IPS: Sits inline. Actively drops packets and resets TCP connections!

📡
NSM & Zeek
Metadata & PCAP

Network Security Monitoring (NSM): Converts raw packets into structured protocol transaction logs (HTTP requests, SSL certs, DNS lookups) and stores PCAP for deep packet inspection.

Hands-on Focus in Week 4 & 5

Adversary Context

🎯 SYNTHESIS WALKTHROUGH

One Attack Traced Across 4 Distinct Data Sources

This real-world attack scenario proves why centralizing multi-source logs is the only way to solve modern cyber incidents:

1. PERIMETER Firewall Log 198.51.100.4 probes 50 ports; finds port 443 open to Web Server (10.0.0.5).
→
2. WEB APP Nginx Access Log 198.51.100.4 exploits SQLi on /search.php and uploads webshell `shell.aspx`.
→
3. HOST KERNEL Sysmon Event 1 `w3wp.exe` spawns `cmd.exe` executing `powershell.exe -enc ...` beaconing out!
→
4. IDENTITY Security Event 4720 Attacker script creates local backdoor account `svc_backup01`.
🧠 The SIEM Correlation Magic CRITICAL INCIDENT

• Alone, the firewall drop was just background internet noise.
• Alone, the web log entry looked like an ordinary web server error.
• Alone, the PowerShell process might have looked like routine IT maintenance.
Only the SIEM correlated all four events across the 25-minute window and raised the alert: "External Exploit leading to WebShell Execution and Backdoor User Creation!"
