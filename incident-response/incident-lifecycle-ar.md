# دورة حياة الحادث وإدارة حالته

> **الحالة:** مسودة  
> **التحقق:** لم يتم التحقق

## 1. النموذج

يستخدم SOC-LAB سير عمل تشغيلياً عملياً يمكن مواءمته مع وظائف الكشف والاستجابة والتعافي والتحسين المستمر في NIST CSF 2.0. ويظل الاستعداد (الحوكمة والتحديد والحماية) مستمراً، ولا ينبغي اعتباره عملاً يبدأ بعد التنبيه فقط.

المراحل أدناه تسلسل تعليمي تشغيلي، وليست ادعاءً بأن كل الحوادث تتبع مساراً خطياً صارماً. قد تتداخل الأنشطة أو تتكرر أو تنفذ بالتوازي.

## 2. المراحل التشغيلية

| المرحلة | الأسئلة الأساسية | المخرجات المعتادة |
|---|---|---|
| الاستعداد والتنسيق | هل الأدوار والصلاحيات وجهات الاتصال والأنظمة والإجراءات جاهزة؟ | مسار اتصال وإجراءات معتمدة ونطاق التمرين |
| الكشف والإبلاغ | ما الإشارة المرصودة ومتى ومن رصدها؟ | مرجع التنبيه أو الحدث والتقرير الأولي |
| التحقق والفرز | هل النشاط موثوق وذو صلة وقد يسبب ضرراً؟ | ملاحظات الفرز وفئة/شدة أولية |
| التحليل وتحديد النطاق | ماذا حدث وما الأصول والهويات والبيانات المعنية وما المجهول؟ | خط زمني ومصفوفة أدلة وبيان نطاق |
| القرار والاحتواء | ما خفض المخاطر الفوري المبرر ومن يجيزه؟ | سجل قرار وإجراءات احتواء معتمدة |
| الإزالة والمعالجة | ما الوصول أو الآلية أو الضعف الواجب معالجته؟ | خطة معالجة وأدلة إنجازها |
| التعافي | كيف تستعاد الخدمات بأمان وتُراقب؟ | تحقق التعافي وخطة المراقبة |
| الإغلاق والتحسين | هل تحققت الأهداف واكتملت السجلات وأُسندت الدروس؟ | مبررات الإغلاق والدروس ومسؤولو الإجراءات |

## 3. حالات الحادث

استخدم حالات السجل المقترحة التالية. تصف الحالة تقدم سير العمل، وليست تصنيفاً للشدة.

- `new`: وصل البلاغ ولم يبدأ فرزه بعد.
- `triage`: يجري التحقق وتحديد الأولوية والنطاق الأولي.
- `investigating`: يجري تحليل الأدلة وتحديد النطاق.
- `contained`: اكتملت إجراءات الاحتواء المعتمدة أو ضُبط الخطر بطريقة أخرى؛ اشرح المخاطر المتبقية.
- `eradication`: تجري إزالة الوصول أو الآليات الخبيثة والمعالجة.
- `recovering`: تجري استعادة الخدمة والمراقبة المعززة.
- `monitoring`: البيئة المستعادة تخضع لمراقبة محددة.
- `closed`: استوفيت معايير الإغلاق وسُجلت المبررات.
- `reopened`: تتطلب أدلة جديدة أو عودة النشاط استئناف الاستجابة.
- `duplicate` / `false-positive` / `benign`: أُغلق السجل مع تفسير وربط بالسجل ذي الصلة عند الاقتضاء.

قد يتراجع الحادث إلى حالة سابقة أو يعود للتحقيق إذا بطلت افتراضات سابقة بأدلة جديدة.

## 4. ضوابط الدخول والخروج والانتقال

سجل لكل انتقال:

- الطابع الزمني والمنطقة الزمنية؛
- الحالة السابقة والجديدة؛
- القرار أو الدليل المؤيد للانتقال؛
- الشخص الذي اتخذ القرار أو أجازه؛
- المخاطر غير المحسومة والإجراء التالي.

لا تصنف الحادث محتوًى لمجرد توقف التنبيه. تحقق مما إذا كان مسار التهديد قد حُظر وما إذا ظل وصول بديل أو أصول متأثرة.

لا تغلق الحادث لمجرد تحديث تذكرة أو إعادة تشغيل نظام.

## 5. معايير الإغلاق

لا يُنظر في الإغلاق إلا عندما:

- يوثق هدف الحادث ونطاقه؛
- تكون نتائج إجراءات الاحتواء والمعالجة معروفة أو تُقبل المخاطر المتبقية صراحةً؛
- تجتاز الخدمات المتأثرة فحوص التعافي المحددة؛
- تحدد المراقبة وملكية المخاطر المتبقية؛
- تسجل مراجع الأدلة والخط الزمني والاتصالات والموافقات؛
- تسند إجراءات المتابعة إلى مسؤولين ومواعيد استحقاق؛
- يكون قرار الإغلاق مصرحاً به.

## 6. حلقة التحسين

سجل فجوات الكشف والقياس الناقص والاحتكاك الإجرائي وغموض الصلاحيات وضعف التعافي واحتياجات التدريب. حوّل النتائج المهمة إلى إجراءات لها مالك، وأدخلها في تحديثات المنهج والمختبر والكشف والحوكمة.
