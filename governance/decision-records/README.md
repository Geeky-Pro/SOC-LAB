# Architecture Decision Records

Use an ADR for decisions that materially affect repository structure, curriculum boundaries, lab architecture, AI workflow, or long-term maintenance.

## Suggested format

- **Status:** proposed, accepted, superseded, or deprecated.
- **Date:** decision date.
- **Context:** problem and constraints.
- **Decision:** selected option.
- **Alternatives:** options considered.
- **Consequences:** trade-offs and follow-up work.
- **Owner:** Project Owner or decision authority.

ADRs are append-only records. Supersede an old decision with a new ADR rather than silently rewriting history.
