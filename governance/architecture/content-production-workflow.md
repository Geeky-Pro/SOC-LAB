# Content Production Workflow

1. **Intake:** identify audience, module, learning outcome, deliverable, constraints, and dependencies.
2. **Context review:** read project standards, existing module content, canonical templates, and authoritative references.
3. **Plan:** define structure, practical requirements, assets, and acceptance criteria.
4. **Draft:** create the content using the relevant skill and canonical template.
5. **Author check:** check completeness, links, terminology, source quality, and safety.
6. **Independent review:** obtain a separate quality review with evidence and findings.
7. **Revision:** address findings or document accepted limitations.
8. **Owner approval:** request explicit Project Owner acceptance.
9. **Release preparation:** validate packaging, access separation, version metadata, and release notes.
10. **Maintenance:** revisit content when tools, versions, references, or learning outcomes change.

A content review is not a substitute for executing a lab. Practical validation must be performed and recorded separately.
