◆ FOUNDATIONS

Anatomy of a URL

Before analyzing a suspicious link, an analyst needs to reliably name every part of it — attackers hide their tricks in specific pieces of this structure.

Hostname
Path
https://
academy.
tcm-sec.
com
/courses/
example.php
?t=129
Protocol
Subdomain
Domain
TLD
Subdirectory
File
Parameter

Now compare that to a real phishing URL — the same structure, but every piece is weaponized:

Hostname — Spoofed
Path
http://
apple-login.
dnsdyn.
net
/ODFTY/
index.php
?email=asimpson@example.com
Protocol
Subdomain
Real domain
TLD
Subdirectory
File
Victim's email

Read every piece: "apple-login" is just a subdomain label, not proof of Apple — the real domain is dnsdyn.net, a dynamic-DNS provider no legitimate company uses for login pages. "ODFTY" is a random, auto-generated subdirectory. And the highlighted parameter pre-fills the victim's own email into the fake login form, both to look more convincing and to let the attacker track exactly who clicked.

◆ METHOD DEEP DIVE

URL Analysis — Analyst Workflow

With the anatomy in hand, a suspicious URL is worked through in three stages — extract, inspect, then scan.

1

Extract the URL

  • Pull every link out of the header and body
2

Check for Red Flags

  • Look for spoofing attempts — look-alike domains and subdomain abuse
  • Watch for URL shorteners hiding the real destination
  • Watch for encoding tricks masking the true link
3

Scan With Tools

  • Submit the URL in its original form — scanning tools need the real link, not a defanged one
  • Cross-reference results to reach a verdict

Never visit a suspicious URL directly. Always use an isolated analysis VM, a dedicated sandbox tool, or a URL-scanning service.

◆ TOOLING

URL Analysis Tools

These services let an analyst safely inspect a URL without ever loading it in a real browser.

SCREENSHOT

URL2PNG

Renders a safe screenshot of the destination page without ever loading it in the analyst's own browser — a quick, low-risk first look at what a link leads to.

FULL SCAN

urlscan.io

Loads the page in an isolated sandbox and captures a screenshot, the full DOM, every network request, and the redirect chain.

REPUTATION

VirusTotal

Submits the URL to dozens of antivirus and blocklist engines at once and returns a consolidated malicious / suspicious / clean verdict.

PHISHING DB

PhishTank

A community-driven database of confirmed phishing addresses — search it to check if a URL is already reported, and to see newly submitted phishing sites as they're verified.

Analyst's tip: A "clean" result from one tool is not proof of safety — brand-new malicious domains are often not yet indexed anywhere. Cross-reference at least two independent sources before clearing a URL.

◆ METHOD DEEP DIVE

Attachment Analysis — Static vs Dynamic

Once an attachment is securely extracted, hash it and search that hash's reputation first — a known-bad hit alone can be enough for a verdict. From there, an analyst has two complementary approaches to dig deeper.

Static Analysis

  • Examines the file without running it
  • Safe, fast, and repeatable at scale
  • PDF: pdfid / pdf-parser to pull out embedded URLs and objects
  • Office doc: oledump to find and extract macros

Dynamic Analysis

  • Executes the file in an isolated sandbox
  • Reveals real runtime behavior and intent
  • Process, file system, registry, network activity
  • Slower, and some malware detects and evades sandboxes

Scope note: Full malware analysis process is outside this course. The goal here is triage — pull out embedded URLs, objects, and macros to confirm intent, or hand the file to a sandbox and read its report.

◆ STATIC ANALYSIS

Static Analysis Techniques

Start every file the same way — hash it and search that hash's reputation. If it comes back unknown, the next tools depend on the file type.

Hash & Search: Compute the file's MD5 / SHA-1 / SHA-256 and search it on VirusTotal and other reputation sources — the fastest check, and often enough to reach a verdict on its own.

PDF Files

1

pdfid

  • Quick triage count of risky keywords — JavaScript, embedded files, launch actions
2

pdf-parser

  • Digs into the flagged objects to pull out embedded URLs and payloads

Office Documents

1

oledump

  • Inspects the OLE structure of Word/Excel files to detect embedded VBA macros
2

Extract & Review

  • Pull out the macro code and read it without ever letting it run

Scope note: The goal is triage, not full reverse engineering — extract the indicator (a URL, an object, a macro), then decide whether it's worth escalating to a sandbox.

◆ DYNAMIC ANALYSIS

Dynamic Analysis & Sandboxing

The file is detonated inside an isolated, monitored environment — an analyst watches what it actually does, rather than guessing from its code alone.

Process Behavior

Which child processes spawn, what commands run, and whether the sample tries to inject into or hollow out other processes.

File System & Registry Changes

New or modified files, dropped payloads, and registry keys added for persistence across reboots.

Network Traffic

Command-and-control callbacks, DNS requests, and any second-stage payload downloads captured with full packet detail.

Sandbox-Evasion Checks

Some malware detects it's being watched — checking for a mouse, a real user, or specific VM artifacts — and stays dormant to avoid analysis.

SANDBOX

Any.Run

Interactive, browser-based sandbox with live process, network, and screen visibility during detonation.

SANDBOX

Joe Sandbox

Deep behavioral reports covering process trees, network activity, and MITRE ATT&CK technique mapping.

SANDBOX

Hybrid Analysis / Cuckoo

Free and open-source options for automated detonation with detailed behavioral reports.

◆ TOOLING

Automated Analysis Tools

Manual analysis doesn't scale to hundreds of reported emails a day — these two tools automate the repetitive parts of the process.

SCRIPT

eioc.py

Parses a raw email file and extracts every IOC in one pass — sender and reply-to addresses, URLs, IPs, and attachment hashes — turning what would be several manual steps into a single command.

WEBSITE

PhishTool

A web-based triage platform — upload the email and it pulls header, URL, and attachment analysis into one case, with a verdict and case management built in.

Analyst's tip: Automation accelerates triage but doesn't replace judgment — a tool's verdict is one input into the analyst's own conclusion, not a substitute for it.

◆ METHOD DEEP DIVE

Defense Measures — Reactive vs Proactive

Once a phishing email is confirmed malicious, the response splits into two tracks: contain what already happened, and reduce the chance it happens again.

Reactive Defense

  • Taken after a confirmed threat is found
  • Focused on containment and eradication
  • Time-sensitive — every minute counts
  • e.g. blocking, quarantining, resetting credentials

Proactive Defense

  • Put in place before an attack occurs
  • Focused on reducing likelihood and blast radius
  • Ongoing, not tied to a single incident
  • e.g. DMARC enforcement, training, threat intel

Analyst's tip: A mature security program treats every reactive response as an input to the proactive program — each incident should improve the defenses that prevent the next one.

◆ REACTIVE DEFENSE

Reactive Phishing Defense

Once a phishing email is confirmed, response moves through five phases — from stopping the spread to closing the loop with training.

1

Containment

  • Determine scope
  • Quarantine
  • Block sender artifacts
  • Block web artifacts
  • Block file artifacts
2

Eradication

  • Remove malicious emails
    • Content search and eDiscovery
  • Remove malicious files
  • Abuse form submissions
  • Credential changes
  • Reimaging
3

Recovery

  • Restore systems
4

Communication

  • Notify affected users
  • Update stakeholders
5

User Education

  • End-user training
◆ PROACTIVE DEFENSE

Proactive Phishing Defense

Standing controls maintained continuously across five layers to reduce both the likelihood and the impact of the next phishing attempt.

1

Email Filtering

  • Email security appliances
  • Marking external emails
2

URL Scanning & Blocking

  • Real-time URL inspection
  • Block recently registered domains
3

Attachment Filtering

  • File extension blocks
  • Attachment sandboxing
4

Email Authentication Methods

  • SPF
  • DKIM
  • DMARC
5

User Training

  • Security awareness training
  • Phishing simulation exercises
  • Reporting functionality

Analyst's tip: No single layer is enough on its own — these five work together, so a phish that slips past filtering can still be stopped by authentication checks, sandboxing, or a trained user reporting it.

◆ METHOD DEEP DIVE

Documentation & Reporting

An incident isn't closed until it's written down — the report turns a one-off response into knowledge the whole team can use.

Institutional Memory

The next analyst may not have handled this incident. A good report lets them spot the same attack instantly.

Compliance & Accountability

Audits, insurance, and regulators often require proof of what was detected, and how it was handled.

Metrics & Trends

Reports add up over time — showing which departments are targeted most, and whether training is working.

Handoff & Escalation

A clear report lets you pass the incident to another team, or up to management, without re-explaining it.

Justify the Response

Don't just list what was done — explain why. State the reasoning behind each action, so anyone reviewing it later understands the decision, not just the outcome.

Analyst's tip: Write for a reader who knows nothing about this incident — spell out acronyms, give a clear timeline, and don't rely on memory only you have.

◆ REPORT TEMPLATE

Incident Report Structure

A consistent structure makes every report easy to skim under pressure and easy to compare against past incidents.

1

Description

  • Plain-language summary of what the email does and why it's suspicious
2

Headers

  • Date, Subject, To, From, Reply-To, Return-Path, Sender IP, Resolved Host, Message-ID
3

URLs

  • Every link extracted from the header and body
4

Attachments

  • Attachment name, MD5, SHA1, and SHA256 for each file
5

Artifact Analysis

  • Sender Analysis, URL Analysis, and Attachment Analysis — findings from each
6

Verdict

  • Final classification — malicious, suspicious, or benign
7

Defense Actions

  • Every reactive step taken in response

Best practice: Defang every URL and IP written into the report — hxxp[://]evil[.]com, 1.2.3[.]4 — so nothing in the document is clickable or gets auto-parsed as a live indicator by whoever reads it next.
