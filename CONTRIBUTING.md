# Contributing to SOC-LAB

## Before contributing

1. Read [AGENTS.md](AGENTS.md) and the [Project Charter](governance/project-charter.md).
2. Review the relevant architecture and policies.
3. Check whether equivalent content already exists in the module or shared project resources.
4. Confirm that the proposed change fits the current curriculum scope.

## Contribution principles

- Prefer competency-based explanations over tool-specific descriptions.
- Make practical instructions reproducible and version-aware.
- Separate instructor-only guidance and answer keys from student-facing material.
- Provide safe lab boundaries, cleanup, and recovery steps.
- Use official vendor documentation and credible primary references.
- Avoid duplicating shared templates, procedures, or configurations.

## Branch and review

Use a focused branch and descriptive commits. Submit substantial content for independent review. A successful Markdown or link check does not establish technical correctness or lab reproducibility.

## Do not contribute

Do not commit credentials, personal student information, unlicensed courseware, proprietary datasets, malware binaries, or VM disk images.
