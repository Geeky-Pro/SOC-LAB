◆ SOC FUNDAMENTALS

ما هو مركز العمليات الأمنية (SOC)؟

هو وحدة مركزية مسؤولة عن المراقبة، الاكتشاف، التحليل، والاستجابة للتهديدات السيبرانية على مدار الساعة.

المراقبة المستمرة

مراقبة الأنظمة والشبكات والهوية على مدار الساعة (24/7) لاكتشاف أي نشاط غير طبيعي.

حماية الأصول

حماية البيانات والأنظمة والبنية التحتية من التهديدات الداخلية والخارجية.

الاستجابة السريعة

تقليل المخاطر من خلال الاحتواء والاستئصال والتعافي من الحوادث.

دورة SOC الأساسية: Monitor → Detect → Analyze → Respond — وهي مستمرة لا تتوقف.

◆ CORE TERMS

الفرق بين Log, Event, Alert, Incident

هذه المصطلحات ليست مترادفة — فهمها هو أساس عمل المحلل.

LOG

السجل

سجل خام (Record) يُنشئه نظام أو تطبيق أو جهاز يوثّق نشاطاً معيناً.

مثال: تسجيل دخول مستخدم في Windows Security Log.

EVENT

الحدث

أي واقعة يمكن ملاحظتها وقد تكون ذات دلالة أمنية.

مثال: محاولات تسجيل دخول فاشلة متعددة.

ALERT

التنبيه

إشعار يُنشأ عندما يطابق نشاط مشبوه قاعدة كشف أو شرطاً محدداً.

مثال: اكتشاف هجوم تخمين كلمات مرور (Brute Force).

INCIDENT

الحادث

حدث أمني مؤكد يتطلب تحقيقاً واستجابة.

مثال: اختراق حساب مستخدم بنجاح.

ليس كل Log يصبح Event، وليس كل Event يصبح Alert، وليس كل Alert يصبح Incident. وظيفة SOC هي الفرز (Triage) في كل مرحلة.

◆ THE WHY

لماذا نحتاج جمع السجلات مركزياً؟

سجلات موزعة على عشرات الأنظمة = عمى أمني. السجلات المركزية تعطينا الرؤية الكاملة.

التحدي: السجلات الموزعة

  • كل نظام يحتفظ بسجلاته محلياً.
  • صعوبة ربط الأحداث عبر أنظمة مختلفة.
  • فقدان السجلات عند إعادة تشغيل الجهاز أو حذفها.
  • لا يمكن اكتشاف هجوم متعدد المراحل.

الحل: المركزية (Centralization)

  • رؤية موحدة (Single Pane of Glass) لكل الأحداث.
  • ربط (Correlation) بين حدث على الشبكة وحدث على الجهاز.
  • الاحتفاظ بالسجلات لفترة أطول والبحث فيها.
  • تمكين الكشف والتحقيق والتحليل المتقدم.

◆ LOG SOURCES

مصادر السجلات: أنظمة التشغيل

Windows Event Logs

سجلات منظمة في قنوات (Channels) رئيسية:

  • Security: تسجيل الدخول، التغييرات الأمنية، الوصول للكائنات.
  • System: أحداث نظام التشغيل، بدء/إيقاف الخدمات، تعريفات الأجهزة.
  • Application: أحداث التطبيقات.
  • PowerShell/Operational: أوامر PowerShell (مهم جداً للكشف).
  • Sysmon/Operational: سجلات تفصيلية للعمليات والشبكة (سنشرحه لاحقاً).

Linux Logs

ملفات نصية في /var/log/ أو سجلات systemd:

  • /var/log/auth.log (Debian/Ubuntu) أو /var/log/secure (RHEL): المصادقة، sudo، SSH.
  • /var/log/syslog أو messages: رسائل النظام العامة.
  • /var/log/audit/audit.log: سجلات auditd (رقابة على مستوى النواة).
  • journalctl: عرض سجلات systemd-journald.

في Linux، السجلات نصية ويمكن قراءتها بأدوات بسيطة مثل cat, tail, grep, less — وهذا يجعل التحليل اليدوي أسهل للمبتدئين.

◆ LOG SOURCES

مصادر السجلات: الشبكة والويب

Firewall & Network Flow

سجلات حركة المرور (Traffic/Flow)، الاتصالات المسموحة والمرفوضة، وعناوين IP المصدر والوجهة والمنافذ.

Proxy & DNS

سجلات الوصول إلى الإنترنت عبر البروكسي، واستعلامات DNS (مصدر ممتاز لكشف الاتصالات الخبيثة بـ C2).

Web Server (Apache/Nginx)

سجلات Access (كل طلب HTTP: IP, URL, الحالة) وError (أخطاء الخادم). تكشف هجمات الويب مثل SQLi وXSS.

# مثال: سطر من Nginx Access Log
192.168.1.10 - - [10/Oct/2026:13:55:36 +0300] "GET /login.php HTTP/1.1" 200 1234 "-" "Mozilla/5.0..."
# الحقول: IP العميل، التاريخ، الطلب، رمز الحالة، حجم الاستجابة
◆ HANDS-ON

عملي: استكشاف السجلات

سنتدرب على قراءة السجلات يدوياً في بيئتينا (Windows وLinux) قبل الانتقال إلى الأدوات المركزية.

🪟 Windows — Event Viewer

افتح eventvwr.msc من قائمة Start.

# عرض سجلات المصادقة الفاشلة
Windows Logs → Security → Filter → Event ID 4625
# عرض إنشاء عملية جديدة
Event ID 4688 (New Process Created)

🐧 Linux — Terminal

استخدم أوامر الطرفية لقراءة السجلات مباشرة.

# محاولات SSH الفاشلة
grep "Failed password" /var/log/auth.log
# متابعة السجلات في الوقت الفعلي
tail -f /var/log/syslog
# سجلات خدمة SSH عبر systemd
journalctl -u sshd --no-pager

النشاط: افتح Event Viewer على جهازك وابحث عن Event ID 4625. كم محاولة فاشلة لديك اليوم؟ ثم على Linux، جرّب journalctl --since "1 hour ago" | grep -i error.

◆ THE TOOLS

كيف نجمع كل هذا؟ (SIEM, EDR, Sysmon)

بعد أن رأينا السجلات الموزعة، نحتاج إلى أدوات تجمعها وتثريها وتحللها.

SIEM

Security Information and Event Management

منصة مركزية تجمع السجلات من كل المصادر، تطبعها (Normalize)، تربط الأحداث (Correlate)، وتُظهر تنبيهات. مثال: Wazuh, Splunk, Elastic.

EDR

Endpoint Detection and Response

وكيل (Agent) يُثبّت على الجهاز ويسجل تفاصيل دقيقة: العمليات، الملفات، الشبكة، الريجستري. يوفر كشفاً واستجابة. مثال: CrowdStrike, Defender for Endpoint.

Sysmon

System Monitor (Microsoft)

أداة مجانية من Sysinternals توفر سجلات تفصيلية جداً (Process, Network, File, Registry) وتُرسَل إلى Event Log ثم إلى SIEM. هي "EDR مجاني" لكن بدون استجابة آلية.
