🔎 DEFENSIVE PHILOSOPHY

The Visibility Imperative: The 6 Forensic Questions

Defenders cannot protect what they cannot see. Every security incident investigation relies on answering 6 fundamental questions:

1. WHO (Subject)
User identity, SID, service account, or machine account initiating the action.
Ex: TargetUserName, UID
2. WHAT (Action)
Specific event executed: process spawned, file modified, registry key created.
Ex: ProcessName, EventID
3. WHEN (Timestamp)
Precise chronological anchor. Must include millisecond precision and UTC offset.
Ex: 2026-10-23T08:14:22Z
4. WHERE (Location)
Source host, destination asset, internal subnet, or external IP geolocation.
Ex: ComputerName, SrcIP
5. HOW (Mechanism)
Vector or tool used: PowerShell script, RDP session, SMB pipe, HTTP POST.
Ex: LogonType, CommandLine
6. OUTCOME (Status)
Did the attempted action succeed or fail? Crucial for brute-force triage.
Ex: Success, Failure (0xC000006A)
Key Principle: If a log source omits even one of these dimensions (e.g. logging an event without recording the user or source IP), the analyst's investigative capability is critically blind.
⚖️ TERMINOLOGY TAXONOMY

Log → Event → Alert → Incident

Understanding the four tiers of security data reduction and investigative escalation:

1. LOG (The Raw Record) VOLUME: 100M+ / DAY
Any timestamped text or binary string recorded by an operating system, application, or network device documenting that an action occurred.
Ex: 10.0.0.5 - - [23/Oct/2026:10:00:01] "GET /index.html" 200 4520
2. EVENT (Structured Significance) VOLUME: 5M+ / DAY
A log that has been parsed, normalized, and categorized into defined fields carrying operational or security meaning.
Ex: Windows Event ID 4625 (An account failed to log on)
3. ALERT (Automated Suspicion) VOLUME: 50 / DAY
A notification triggered when an event or sequence violates a detection rule, threshold, or behavioral anomaly baseline.
Ex: "Rule Fired: 15 Failed Logons in 60s from External IP"
4. INCIDENT (Verified Breach) VOLUME: 1-2 / WEEK
A validated security alert confirming unauthorized access, data compromise, or active malware requiring formal containment.
Ex: Active ransomware execution spreading via PsExec on DC
Funnel Ratio: Raw Telemetry (100,000:1) → Parsed Events (1,000:1) → Triage Alerts (10:1) → Security Incident (1)
📚 ENTERPRISE TAXONOMY

The 8 Primary Enterprise Log Types

Every corporate IT infrastructure generates telemetry across eight standardized functional domains:

📱 Application Logs
Messages about specific business apps, runtime status, errors, warnings, and transaction steps.
Ex: ERP errors, CRM logins, Java stack traces, custom API logs
📜 Audit Logs
Activities related to operational procedures, user management, and compliance governance.
Ex: SOX, PCI-DSS §10, HIPAA audit trails, policy changes
🔓 Security Logs
Direct security-relevant events: logins, failed auth, permission changes, and firewall activity.
Ex: Event 4624/4625, sudo escalation, firewall rule triggers
🖥️ Server Logs
Composite telemetry generated by host servers: system, event, error, uptime, and access metrics.
Ex: Host resource exhaustion, service failures, scheduled tasks
⚙️ System Logs
Kernel activities, OS subsystem messages, device drivers, boot sequences, and hardware health.
Ex: /var/log/kern.log, Windows System.evtx, crash dumps
🌐 Network Logs
Network traffic flow, stateful connections, NAT translations, routing updates, and DNS lookups.
Ex: NetFlow/IPFIX, DNS query logs, VPN tunnel disconnects
💾 Database Logs
Activities within DBMS systems: queries executed, table updates, administrative schema alterations.
Ex: PostgreSQL pg_log, MySQL general_log, MSSQL audit
🌍 Web Server Logs
Inbound HTTP/S requests processed by web servers: URLs, response status codes, User-Agents.
Ex: Apache access.log, Nginx combined format, IIS W3C

The Enterprise Telemetry Landscape: 4 Ingestion Tiers

Holistic visibility requires capturing signals across all four operational tiers of the infrastructure:

💻 Tier 1: Host & Endpoint Telemetry DEEPEST CONTEXT
Sources: Windows Workstations, Linux Servers, macOS Laptops.
Artifacts: Process spawning trees (Sysmon Event 1), DLL injection, registry persistence, CLI arguments, local user authentications (PAM/Kerberos).

Sources: Next-Gen Firewalls (Palo Alto, Fortinet), IDS/IPS (Suricata, Snort), DNS resolvers, NetFlow/IPFIX, VPN gateways.
Artifacts: Port scans, outbound C2 beaconing, DNS tunneling, protocol anomalies.

🔑 Tier 3: Identity & Access (IAM) Telemetry CRITICAL FOCUS
Sources: Active Directory (DC Security logs), Entra ID, Okta, PingFederate.
Artifacts: Kerberoasting (Event 4769), Golden Ticket, MFA fatigue attacks, impossible travel logins, Group Policy edits.
Value: Unmasks compromised credentials before ransomware deployment.
☁️ Tier 4: Cloud & SaaS Telemetry DYNAMIC PERIMETER
Sources: AWS CloudTrail, Azure Activity, Google Cloud Audit, Microsoft 365, GitHub.
Artifacts: S3 bucket permission changes, IAM role assumptions, mass email forwards, API token generation.
Value: Protects modern cloud workloads and hybrid remote infrastructure.
🔬 DATA STRUCTURE

Anatomy of a Log Entry: Raw Text vs Structured JSON

Comparing legacy unstructured syslog with modern JSON/ECS key-value schemas:

⚠️ Legacy Unstructured Log HIGH COMPUTATIONAL COST
/var/log/auth.log
Oct 23 08:14:22 web-prod-01 sshd[28491]: Failed password for invalid user admin from 198.51.100.44 port 51234 ssh2
  • Must be parsed using heavy Regular Expressions (Regex/Grok).
  • Fields are not explicitly labeled (hard to distinguish user from IP).
  • Slow to index and expensive to query across billions of rows.
✅ Modern Structured Schema (JSON / ECS) INSTANT FILTERING
Elastic Common Schema (ECS)
{ "@timestamp": "2026-10-23T08:14:22.104Z", "host.name": "web-prod-01", "event.category": "authentication", "event.outcome": "failure", "user.name": "admin", "source.ip": "198.51.100.44", "source.port": 51234, "service.name": "sshd" }
  • Key-value pairs allow instant relational filtering in SIEM.
  • Enables automated correlation rules without custom parsing.
📄 ENCODINGS & SCHEMAS

Log Formats & Standards: Syslog, CLF, EVTX, and CEF

The industry standards that govern how security events are formatted and interchanged:

1. Syslog (RFC 5424)
Unix standard. Uses Priority:
PRI = (Facility × 8) + Severity.
<34>1 2026-10-23T08:00:00Z fw01 filterlog - - Action=BLOCK Proto=TCP
2. Web CLF Format
De facto standard for Apache and Nginx recording HTTP metadata.
10.0.0.5 - alice [23/Oct/2026] "GET /login.php HTTP/1.1" 200 3412
3. Windows XML (.evtx)
Proprietary Microsoft binary format split into <System> and <EventData>.
<Event><System><EventID>4624</EventID></System><EventData>...</Event>
4. CEF / ArcSight
Standardized pipe-delimited format for network appliances and SIEM.
CEF:0|Vendor|Device|1.0|100|Port Scan|8|src=10.0.0.5 dst=10.0.0.10
🪟 ENDPOINT TELEMETRY: WINDOWS

Windows Event Logging Architecture (.evtx)

The Windows Event Log subsystem records operational and security state changes in structured XML files:

📂 Core Event Channels & Paths
All modern logs are stored in %SystemRoot%\System32\Winevt\Logs\*.evtx:
  • Security.evtx: User authentication, privilege assignment, process creation, audit policy changes. (Restricted to Admins).
  • System.evtx: Device drivers, OS boot, hardware faults, service control manager (Service installs: Event 7045).
  • Application.evtx: Software crashes, third-party agents, database errors.
  • ForwardedEvents.evtx: Aggregated logs received via Windows Event Forwarding (WEF).
  • Applications & Services: Granular sub-channels like PowerShell Operational (Script Block 4104) and TaskScheduler.
🚨 Top High-Fidelity Security Event IDs
Event ID Name Security Focus
4624 Successful Logon Check LogonType (2: Console, 3: Network, 10: RDP)
4625 Failed Logon Brute-force detection, sub-status (0xC000006A bad pass)
4672 Special Privileges Administrator / SeDebugPrivilege assignment
4688 Process Created Command line auditing (Requires GPO enablement)
4720/4726 User Created/Deleted Backdoor persistence & forensic anti-evidence cleanup
TIP: Always correlate Event 4625 clusters followed immediately by Event 4624.
🧠 DEEP HOST TELEMETRY

Sysmon: Bridging Endpoint Visibility Gaps

System Monitor (Sysmon) provides kernel-level driver telemetry to expose stealthy adversary behavior:

⚠️ The Built-In Windows Visibility Blind Spot
  • No Parent Lineage: Native 4688 does not reliably capture the full parent process command line or execution hierarchy.
  • Missing Hashes: Does not calculate cryptographic file hashes (SHA256/MD5) of executed binaries at runtime.
  • No Network Attribution: Native logs cannot tell you which process PID initiated an outbound TCP connection.
  • No DNS Resolution Tracking: Cannot see what domains malware queried before connecting to C2.
Result: Attackers using Living-off-the-Land Binaries (certutil, mshta, powershell) remain virtually undetected without Sysmon.
🛡️ Essential Sysmon Event IDs (Channel: Sysmon/Operational)
Event 1: Process Creation
Records exact CommandLine, ParentCommandLine, ParentImage, and SHA256 hashes.
Event 3: Network Connection
Links process binary (Image) with SourceIp, DestinationIp, and port.
Event 7: Image Loaded
Detects DLL side-loading, process hollowing, and unauthorized driver injection.
Event 22: DNS Query
Captures the queried domain name, query status, and initiating process ID.

🐧 ENDPOINT TELEMETRY: LINUX

Linux Logging Architecture, rsyslog & journalctl

Understanding the /var/log directory, syslog facilities, systemd journal, and log rotation:

📁 Critical Log Files in /var/log
  • /var/log/auth.log (Ubuntu/Debian) or /var/log/secure (RHEL): SSH logins, PAM authentication, sudo executions, user additions.
  • /var/log/syslog or /var/log/messages: General operating system events, daemons, cron jobs, network interfaces.
  • /var/log/kern.log: Kernel ring buffer messages, hardware drivers, iptables firewall drops.
  • /var/log/audit/audit.log: Linux Audit Daemon (auditd) recording syscalls, file integrity (FIM), and binary executions.
Configured via: /etc/rsyslog.conf & /etc/rsyslog.d/*.conf
⚙️ Facilities, Severities & Maintenance
Syslog Facilities: auth, authpriv, cron, daemon, kern, mail, local0-7.
8 Severity Levels (0 to 7):
0: Emerg 1: Alert 2: Crit 3: Error 4: Warn 5: Notice 6: Info 7: Debug
Logrotate Subsystem (/etc/logrotate.conf): Automatically compresses historical logs (auth.log.1, auth.log.2.gz) to prevent disk exhaustion.

🌐 APPLICATION TELEMETRY: WEB

Web Server Logging: Combined Log Format (CLF)

Web servers (Apache, Nginx) sit on the perimeter, recording every inbound HTTP/S interaction:

📐 Anatomy of NCSA Combined Log Format
192.168.1.50 - frank [23/Oct/2026:14:32:10 +0000] "GET /admin/dashboard.php?user=1 HTTP/1.1" 200 4523 "https://google.com" "Mozilla/5.0 (Windows NT 10.0; Win64; x64)..."
1. Client IP: 192.168.1.50
2. Auth User: frank
3. Timestamp: 23/Oct/2026 UTC
4. Request: GET URI + HTTP
🎯 Security Significance of HTTP Status Codes
  • 200 OK: Request succeeded. If target was a webshell or vulnerable script, exploitation was successful!
  • 401/403: Unauthorized or Forbidden. Web Application Firewall (WAF) or authentication block.
  • 404 Not Found: Resource missing. Spikes of 404s indicate dirbusting / web reconnaissance (Nikto, Gobuster).
  • 500 Internal Error: Unhandled backend exception. Often caused by unescaped quotes in SQL Injection!
🔎 Reconnaissance vs Exploitation
Reconnaissance Signature: Thousands of requests in seconds targeting /admin/, /wp-login.php, /phpmyadmin/ with non-standard User-Agents (sqlmap, python-requests, curl).

Exploitation Signature: Specific URI query strings containing encoded characters (%27 for ', %2e%2e%2f for ../) followed by anomalous response sizes.

⚠️ DECENTRALIZATION COLLAPSE

The Centralization Dilemma: The “Islands of Logs” Trap

Why decentralized, host-by-host log analysis completely breaks down in modern enterprise environments:

🏝️ 1. Disconnected Silos
In a network with 2,000 workstations and 300 servers, an analyst must manually RDP or SSH into dozens of machines to collect evidence, wasting hours during active breaches.
⏳ 2. Finite Storage Overwrite
Local Windows Security event log defaults to only 20 MB. During high activity or brute-force, critical security logs overwrite themselves in less than 3 hours!
🧟 3. Anti-Forensic Tampering
Once an adversary obtains local root or SYSTEM privileges, their very first command is often wevtutil cl Security or rm -rf /var/log/*, destroying all local evidence.
💡 Operational Reality: You cannot cross-correlate a web exploit on Linux with an admin logon on Windows if the logs never meet in a single database!
⏱️ FORENSIC INTEGRITY

Time Synchronization (NTP) & Forensic Evidentiary Integrity

Why microsecond clock precision and tamper-proof storage are the bedrocks of digital forensics:

🕒 Network Time Protocol (NTP) & Clock Skew
If two servers differ by even 45 seconds, the chronological sequence of an attack breaks:
  • Clock Skew Hazard: Lateral movement appears to occur before the initial exploit.
  • Mandatory Standard: All enterprise nodes must sync via authenticated NTP (UDP 123) to Stratum-1 time servers.
  • Strict UTC: All log timestamps must be recorded in UTC (Zulu Time) with millisecond precision to eliminate Daylight Saving confusion.
🔒 Evidentiary Integrity & Chain of Custody
For logs to be legally admissible in court or regulatory audits (PCI-DSS §10.5):
  • WORM Storage: Write Once, Read Many disk appliances prevent alteration by rogue administrators.
  • Cryptographic Hashing: Continuous SHA-256 block hashing verifies logs have not been retroactively altered.
  • Strict Separation of Duties: System admins cannot access or delete SIEM logs.
🌉 THE ARCHITECTURAL BRIDGE

Why Enterprise Security Demands Log Centralization

The four non-negotiable imperatives driving the shift from local logging to centralized SIEM:

🧩 1. Cross-Source Multi-Vector Correlation
Adversaries do not attack in silos. An attack starts with a Phish (Email log), moves to a PowerShell download (Sysmon), triggers a firewall outbound connection (Network log), and moves laterally (Active Directory log). Only a central engine connects these dots.
🛡️ 2. Immutable Anti-Tampering Protection
Centralized log shippers stream events in real time to the SIEM. Even if an attacker gains Domain Admin and deletes local event logs, the evidence is already safely indexed on remote, read-only SIEM servers.
⚡ 3. Sub-Second Enterprise Threat Hunting
When a new zero-day C2 IP is published, an analyst cannot query 5,000 servers one by one. A centralized Lucene/Elasticsearch index enables querying 10 billion events across the entire enterprise in under 2 seconds.
📜 4. Regulatory Compliance & Hot/Cold Retention
Regulations (PCI-DSS §10.7, ISO 27001, HIPAA) mandate 365 days of searchable log retention. Centralized data tiers (Hot NVMe, Warm SSD, Cold S3 glacier) optimize storage costs while satisfying legal audits.
🚛 INGESTION MECHANISMS

Log Shipping Architecture: Agent-Based vs Agentless

How telemetry is transported from distributed endpoints and appliances into the central collector:

📦 Agent-Based Shipping HIGH RELIABILITY
A lightweight daemon installed directly on each operating system (e.g. Wazuh Agent, Elastic Agent, Splunk Forwarder).
  • ✓ Local Disk Buffering: If SIEM is unreachable, logs queue locally; zero packet loss.
  • ✓ Encrypted Transport: Mutual TLS (mTLS) with client certificate verification.
  • ✓ Local Pre-filtering: Drops noisy debug logs before traversing WAN bandwidth.
  • × Trade-off: Requires endpoint software deployment and lifecycle management.
🌐 Agentless Forwarding ZERO ENDPOINT FOOTPRINT
Relies on native protocols and remote polling (e.g. Syslog 514 UDP/TCP, Windows WEF, Cloud REST APIs).
  • ✓ Ideal for Appliances: Essential for closed network firewalls, switches, and IoT where installing third-party agents is impossible.
  • ✓ Cloud Ingestion: Pulls AWS CloudTrail / Azure EventHub via serverless APIs.
  • × Trade-off: UDP Syslog drops packets under heavy load with no retransmission buffer.

🧩 DETECTION LOGIC

SIEM Deep Dive: Multi-Source Correlation Rules

How correlation engines detect complex attack behaviors across sliding time windows:

🎯 The 3 Correlation Architectures
1. Threshold Rules:
Fires when frequency exceeds a limit within a sliding window.
Logic: > 10 failed logins (4625) from same IP within 60 seconds.
2. Sequence / State Rules:
Fires when Event A is strictly followed by Event B.
Logic: Web exploit attempt (HTTP 500) → followed by reverse shell spawned by www-data within 30 seconds.
3. Statistical / Anomaly Rules:
Detects deviations from machine-learning baselines.
Logic: Outbound data volume > 3 standard deviations above 30-day baseline for user.

⚖️ TECHNOLOGY COMPARISON

EDR vs SIEM: Complementary Host & Log Defenses

Understanding why enterprise SOCs require both wide-angle aggregation and deep host response:

Evaluation Dimension SIEM (Security Information & Event Mgmt) EDR (Endpoint Detection & Response)
Scope of Visibility Enterprise-wide: Endpoints, Firewalls, Cloud, Identity, Apps Host-centric: Workstations and Servers only
Telemetry Depth Logs, event records, syslog, API streams Deep kernel hooks: memory inspection, DLL injection, API calls
Primary Function Cross-source correlation, compliance retention, threat hunting Behavioral attack blocking, fileless malware prevention
Active Containment Passive alerting (requires SOAR or manual dispatch to act) ✓ Active Immediate: Network isolation, kill process, quarantine file
Analogy The Wide-Angle Radar Room The Armed Security Guard on the Room Door

🧠 Threat Intelligence (TIP / MISP) IOC FEEDS
Aggregates global indicators of compromise (IoCs) and adversary telemetry:
  • Open-Source TIP (MISP): Shares real-time malware hashes, malicious domains, and C2 IPs using STIX/TAXII.

  • Confidence Scoring: Tags IOCs with reliability ratings to prevent false-positive alert floods.
