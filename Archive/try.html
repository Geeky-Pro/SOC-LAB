👁️ SECTION 1 · PHILOSOPHY OF DEFENSE

The Visibility Imperative & The 6 Forensic Questions

“You cannot defend what you cannot see, and you cannot investigate what was never recorded.”

When a security incident occurs, gut feelings are useless. Analysts rely strictly on telemetry to reconstruct the truth by answering the 6 Forensic Questions:

1. WHO? (Identity)Actor

Which user account, Security Identifier (SID), service account, or API token initiated the request? Were privileges elevated?

2. WHAT? (Action)Activity

What specific operation occurred? Process execution, user creation, registry modification, file deletion, or database query?

3. WHEN? (Timeline)Timestamp

What was the exact UTC timestamp? Establishing an accurate chronological sequence of events is the backbone of incident reconstruction.

4. WHERE? (Location)Asset

Which source IP, workstation hostname, destination server, port, or cloud region generated and received the activity?

5. HOW? (Mechanism)Vector

Which parent process spawned the binary? What command-line arguments, protocol (SSH/RDP/HTTP), or logon type was used?

6. OUTCOME? (Result)Status

Did the action succeed or fail? (e.g., Windows Event 4624 Success vs 4625 Failure; HTTP 200 OK vs 403 Forbidden).

🔍 SECTION 1 · CORE TERMINOLOGY

What is a Log? & The Security Escalation Funnel

What is a Log? A log is an immutable, timestamped digital record generated by an OS, application, or network device to document an activity or state change. Why do we need logs? Without logs, we have zero visibility into system health, regulatory compliance, threat detection, or post-breach root-cause forensics.

1. RAW LOG
Millions / day
The raw text or binary line written to disk documenting any routine or security action (e.g., a line in access.log or Security.evtx).
2. EVENT
Thousands / day
A parsed, observable occurrence extracted from logs that carries operational or security meaning (e.g., "User login attempt via RDP").
3. ALERT
Dozens / day
A notification triggered when an event (or correlated sequence of events) matches a detection rule or anomaly threshold, requiring analyst triage.
4. INCIDENT
Few / month
A verified True Positive security breach confirmed after analyst triage that threatens Confidentiality, Integrity, or Availability (CIA) and demands response.
📂 SECTION 1 · LOG TAXONOMY

The 8 Core Types of Enterprise Logs

Across modern IT infrastructures, telemetry is categorized into eight primary functional log types:

1. Application LogsApp

Messages about specific software applications, including runtime status, exceptions, errors, warnings, and custom app transactions.

2. Audit LogsCompliance

Chronological records of activities related to operational procedures, administrative changes, and data access crucial for regulatory compliance.

3. Security LogsSecOps

Dedicated security events such as user logins, failed authentications, permission/ACL changes, privilege escalations, and firewall activity.

4. Server LogsHost

Various operational logs a server generates across its services, including daemon status, event, error, and resource access logs.

5. System LogsOS/Kernel

Operating system kernel activities, driver loading, system errors, boot sequences, service crashes, and hardware health status.

6. Network LogsWire

Records of network traffic, socket connections, bandwidth flows (NetFlow), DNS lookups, VPN sessions, and routing events.

7. Database LogsData

Activities within a database management system (SQL/NoSQL), such as queries, table updates, schema alterations, and bulk data exports.

8. Web Server LogsHTTP/S

HTTP/HTTPS requests processed by a web server (Apache, Nginx, IIS), including client IPs, requested URLs, User-Agents, and response codes.

🌐 SECTION 1 · TELEMETRY DOMAINS

Enterprise Telemetry Landscape: The 5 Domains

To achieve complete attack surface visibility, a SOC collects and correlates telemetry across five core domains:

1. Endpoints & HostsWorkstations/Servers

Windows EVTX, Sysmon kernel telemetry, Linux /var/log & auditd, macOS Unified Logs, and EDR behavioral telemetry.

2. Network PerimeterSwitches/Firewalls

Next-Gen Firewalls (Palo Alto, Fortinet), NIDS/NIPS (Suricata, Snort), Zeek metadata, DNS query logs, and Proxy/VPN gateways.

3. Identity & AccessIAM / Directory

Active Directory Domain Controllers (Kerberos/NTLM), Microsoft Entra ID (Azure AD), Okta SSO, MFA logs, and PAM vaults.

4. Applications & DBsBusiness Logic

Web servers (Apache, Nginx, IIS), Web Application Firewalls (WAF), SQL/Oracle audit trails, and ERP/CRM application logs.

5. Cloud & SaaSControl Plane

AWS CloudTrail & GuardDuty, Azure Activity Logs, Google Cloud Audit Logs, Kubernetes API logs, and M365 Unified Audit Logs.

Why Multi-Domain Matters

Adversaries move across domains: Phishing (Email) → Execution (Endpoint) → Token Theft (Identity) → Lateral Movement (Network) → Exfiltration (Cloud).

🧬 SECTION 1 · STRUCTURAL ANATOMY

Anatomy of a Log Entry: Unstructured vs Structured

A log entry is composed of specific forensic fields (Header + Payload). How those fields are organized determines how easily a SIEM can parse them:

1. Unstructured Text Log (Requires Regex Parsing)
# Classic Linux Syslog Entry: Oct 23 08:42:19 prod-db01 sshd[1842]: Failed password for invalid user admin from 185.220.101.7 port 54122 ssh2 # Pros: Human-readable, compact on disk. # Cons: Field positions shift per application; requires complex Regular Expressions (Regex) to extract fields.
2. Structured JSON Log (Machine-Ready Key-Value)
{ "@timestamp": "2026-10-23T08:42:19.104Z", "host.hostname": "prod-db01", "process.name": "sshd", "process.pid": 1842, "event.outcome": "failure", "user.name": "admin", "source.ip": "185.220.101.7", "source.port": 54122 }
Timestamp & Zone

Exact time of occurrence, ideally in ISO-8601 UTC format.

Source Identifier

Hostname, IP address, and application/daemon name + PID.

Severity / Priority

Urgency level (Emergency, Alert, Error, Warning, Info).

Event Message

The payload detailing actor, target object, action, and status.

🪟 SECTION 2 · WINDOWS TELEMETRY

Windows Logging Architecture & Channels (.evtx)

Windows records telemetry via the Windows Event Log Service (`svchost.exe -k LocalServiceNetworkRestricted`) into binary XML `.evtx` files stored at C:\Windows\System32\winevt\Logs\:

1. Security Channel

Controlled by Local Security Authority (`lsass.exe`). Logons, privileges, process audit, account changes.

2. System Channel

OS services, kernel drivers, boot/shutdown events, and new service installations (Event 7045).

3. Application Channel

Events logged by user-mode software (SQL Server, Exchange, Antivirus, application crashes).

4. App & Services Logs

Granular feature channels: PowerShell Operational (4104), Task Scheduler, RDP, Windows Defender, and Sysmon.

Event ID Channel Event Meaning SOC Analyst Investigation Focus
4624 / 4625 Security Successful Logon / Failed Logon Check Logon Type (2=Local, 3=SMB/Net, 10=RDP), Source IP, and Failure Status code.
4688 Security A new process has been created Inspect Process Command Line and Creator Process Name (Parent).
4720 / 4732 Security User Created / Added to Local Admins Detect unauthorized backdoor accounts and privilege escalation.
4698 / 7045 Security / System Scheduled Task Created / Service Installed Primary persistence mechanisms used by malware to survive reboots.
1102 / 4104 Security / PowerShell Audit Log Cleared / Script Block Logged 1102 = Anti-forensic cover-up; 4104 = Captures de-obfuscated PowerShell script blocks.
⚙️ SECTION 2 · ADVANCED WINDOWS TELEMETRY

Sysmon: Bridging Windows Visibility Gaps

Standard Windows logs lack file hashes, process-to-network mapping, and DNS query visibility. Microsoft Sysmon (System Monitor) installs as a kernel driver and logs deep telemetry to Microsoft-Windows-Sysmon/Operational:

Sysmon Event ID 1: Process Creation Execution & Lineage

Records every newly spawned process with cryptographic hashes (SHA256, IMPHASH), full CommandLine, ParentProcessId, ParentImage, and ParentCommandLine.

EventID: 1 (Process Create) Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe CommandLine: powershell.exe -nop -w hidden -c "..." ParentImage: C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE Hashes: SHA256=A1B2C3D4E5F6...
Sysmon Event ID 3: Network Connection C2 & Exfiltration

Windows Firewall logs don't tell you which process opened a socket. Sysmon Event 3 binds TCP/UDP network connections directly to the exact Process ID, Image, and User!

EventID: 3 (Network Connection detected) Image: C:\Users\Public\svchost_update.exe User: CORP\jdoe Protocol: tcp | SourceIp: 10.0.0.15 | SourcePort: 53210 DestinationIp: 185.220.101.45 | DestinationPort: 4444
Event ID 11: FileCreateDropper

Detects malware dropping executables or scripts into %TEMP%, AppData, or Startup folders.

Event ID 12/13: RegistryPersistence

Monitors Run/RunOnce registry key creations and modifications used for persistence.

Event ID 22: DNSEventC2 Lookup

Records every domain name resolved and the exact process executable that requested it.

🐧 SECTION 2 · LINUX TELEMETRY

Linux Logging Architecture & rsyslog

Linux centralizes host logging through two primary services: systemd-journald (collects kernel/service logs) and rsyslog (routes logs by Facility.Severity to files in /var/log/ or remote SIEM servers):

Linux Log File Path Purpose & Security Evidence
/var/log/auth.log Debian/Ubuntu
/var/log/secure RHEL/CentOS		 SSH logins, sudo command executions, PAM authentication failures, user/group creation (useradd).
/var/log/syslog / messages General system daemon logs, cron jobs, systemd service starts/stops, network errors.
/var/log/audit/audit.log Linux Kernel Audit daemon (auditd) tracking syscalls, file integrity, and SELinux violations.
/var/log/wtmp & btmp Binary logs of historical logins (read via last) and failed login attempts (read via lastb).
How rsyslog Routes Telemetry/etc/rsyslog.conf

Every syslog message is tagged with a Facility (who generated it: authpriv, kern, daemon, mail) and a Severity Level (0=Emergency to 7=Debug).

/etc/rsyslog.conf — Local & Remote SIEM Forwarding
# Store all auth/security events locally: auth,authpriv.* /var/log/auth.log # Forward ALL logs over TCP (@@) port 514 to central SIEM: *.* @@10.0.0.100:514

🌍 SECTION 2 · WEB TELEMETRY

Web Server Logging: Combined Log Format Dissected

Web servers (Apache in /var/log/apache2/access.log and Nginx in /var/log/nginx/access.log) use the standardized NCSA Combined Log Format:

Anatomy of a Combined Log Format Entry
198.51.100.42 - frank [23/Oct/2026:11:20:05 +0000] "GET /admin/config.php?id=1 HTTP/1.1" 403 1420 "https://portal.corp.local/login" "Mozilla/5.0 (X11; Linux x86_64) sqlmap/1.7"
1. Client IP & User

198.51.100.42 (Source IP) and frank (HTTP Basic Auth user, or - if anonymous).

2. Method & URI

HTTP Verb (GET, POST) and exact URL path + query string parameters.

3. Status & Bytes

403 (Forbidden) and 1420 (Response size in bytes; huge spikes indicate data dump).

4. Referer & Agent

Originating page and User-Agent string (often reveals scanners like sqlmap, nikto, nmap).

Forensic Meaning of HTTP Status Codes

• 200 OK: Request succeeded (Dangerous if seen on an exploit URI or webshell!).  • 401 / 403: Auth failure / Directory access denied.
• 404 Not Found: High volume of 404s from one IP = Directory/File fuzzing scan (Gobuster/Dirb).  • 500 Internal Error: Backend database/script crashed (Strong indicator of active SQLi probing!).

🛠️ SECTION 3 · STANDALONE LOG TOOLING

Traditional Host Log Analysis Tools

When investigating standalone machines or offline forensic images without a SIEM, analysts rely on five core local analysis tools:

1. Windows Event ViewerBuilt-in GUI

Native Windows MMC snap-in (eventvwr.msc). Supports basic Event ID filtering and Custom XML XPath queries, but becomes slow when parsing large `.evtx` files (>100MB).

2. EvtxECmd & Timeline ExplorerEric Zimmerman

EvtxECmd parses millions of binary `.evtx` records into normalized CSV files in seconds. Timeline Explorer loads those CSVs into a blazing-fast filterable grid.

3. Log2Timeline / PlasoSuper Timeline

The gold-standard DFIR tool that extracts timestamps from EVTX, Registry, Browser history, MFT, and Linux logs into one unified chronological Super Timeline.

4. Chainsaw & HayabusaSigma Hunting

High-speed Rust-based CLI threat hunting tools that scan `.evtx` folders against thousands of community Sigma Detection Rules in seconds to flag attacks automatically.

5. Microsoft Log Parser 2.2SQL on Logs

Classic CLI utility allowing analysts to query EVTX, IIS Web Logs, and CSV files using standard SQL syntax (SELECT IpAddress, COUNT(*) FROM Security.evtx GROUP BY IpAddress).

6. Native CLI Text ToolsPowerShell / Bash

Get-WinEvent, wevtutil on Windows, and grep, awk, sed, jq (for JSON logs) on Linux for rapid on-box triage.

🏝️ SECTION 3 · THE ARCHITECTURAL CRISIS

The Centralization Dilemma: “Islands of Logs”

Traditional tools (`eventvwr.msc`, `grep`, `Timeline Explorer`) work well on a single machine. In an enterprise with 5,000 hosts, keeping logs stored locally creates four fatal blind spots:

🗑️
1. Evidence Destruction (Anti-Forensics)

Once an attacker compromises a host and gains Admin/root privileges, their first command is wevtutil cl Security or rm -rf /var/log/*. If logs live only on the local disk, the crime scene is erased forever.

⏳
2. Mathematical Impossibility of Manual Triage

If an attacker pivots across 40 servers, an analyst cannot manually RDP/SSH into 5,000 machines to run `Get-WinEvent` or `EvtxECmd`. Investigating a single indicator would take weeks.

🧩
3. Isolated Silos & Zero Correlation

The Firewall sits in one room, Active Directory in another, and Linux Web Servers in the cloud. No human can mentally cross-reference millions of lines across disconnected consoles in real time.

💾
4. Local Log Rollover (Circular Overwriting)

Local Windows `.evtx` files have a default maximum size (often 20MB–128MB). High-volume activity overwrites old events within hours, destroying historical breach evidence.

⏰ SECTION 3 · CHRONOLOGICAL INTEGRITY

Time Synchronization (NTP) & Forensic Integrity

When investigating an attack across multiple servers, time is the glue that binds evidence together. If server clocks drift apart, forensic reconstruction collapses:

The Clock Skew NightmareBroken Timeline
# Without NTP Synchronization: Firewall Log: 14:00:05 → External IP connects to Web Server Web Server Log: 13:52:10 → Webshell executed (Clock is 8 mins behind!) AD Server Log: 14:01:20 → Kerberos ticket requested

Result: In the timeline, the Webshell appears to execute 8 minutes before the attacker even connected through the firewall! Automated correlation rules fail completely, and legal admissibility is ruined.

The Solution: NTP + UTC + IntegrityBest Practice
  • Network Time Protocol (NTP): Force all routers, firewalls, servers, and endpoints to sync continuously (UDP Port 123) to a Stratum-1/2 authoritative time server.
  • Standardize on UTC: Log all timestamps in Coordinated Universal Time (UTC / ISO-8601) to eliminate daylight-saving and multi-timezone confusion.
  • Log Integrity (WORM & Hashing): Ship logs immediately to a Read-Only central vault with cryptographic hashing so neither attackers nor rogue admins can alter historical records.

Every limitation of traditional, local log analysis directly defines why the SIEM (Security Information and Event Management) was invented:

🚚 SECTION 3 · TELEMETRY TRANSPORT

Log Shipping Architecture: Agents vs Agentless

To move logs from thousands of sources into a central repository in real time, engineers use two primary collection methods:

1. Agent-Based Shipping Workstations & Servers

A dedicated lightweight forwarder service installed on the OS (e.g., Splunk Universal Forwarder, Elastic Beats / Agent, Wazuh Agent, NxLog).

  • Local Disk Queuing: Caches logs locally if the network link drops, ensuring zero data loss.
  • TLS Encryption & Compression: Protects sensitive log data in transit and reduces bandwidth.
  • Granular Filtering: Can filter out noisy events at the source before shipping.
2. Agentless Shipping Network Gear & Cloud

Used where installing software agents is impossible (routers, switches, firewalls, IoT, and SaaS cloud platforms).

  • Syslog Push: Appliances stream Syslog over UDP 514 (fast, connectionless) or TCP/TLS 6514 (reliable, encrypted).
  • Windows Event Forwarding (WEF): Native agentless Windows push over WinRM/Kerberos to a Windows Event Collector (WEC).
  • Cloud REST APIs / Webhooks: SIEM polls AWS CloudTrail, M365, and Okta APIs directly.

🧠 SECTION 4 · SIEM DEEP DIVE

SIEM Deep Dive: The Power of Correlation Rules

A SIEM's greatest strength is stateful multi-source correlation—connecting weak signals across different layers into high-confidence detections:

Core Capabilities of an Enterprise SIEM
  • Sub-Second Search (SPL / KQL / EQL): Query billions of historical logs across months of retention during threat hunting.
  • Threshold & Sequence Rules: Trigger alerts when Event A is followed by Event B within X minutes from the same entity.
  • Anomaly & UEBA Baselining: Detect deviations from normal user behavior (e.g., first-time access to a domain controller at 3:00 AM).
  • Dashboards & Compliance: Real-time SOC wallboards and audit reporting.
Anatomy of a Multi-Stage Correlation Rule
# Rule Name: "Brute Force Followed by Privileged Lateral Movement" CONDITION 1: Count(EventID=4625) >= 20 GROUP BY Source_IP, Target_User WITHIN 5m FOLLOWED BY CONDITION 2: EventID=4624 (LogonType=3 or 10) WHERE Source_IP == Condition1.Source_IP WITHIN 2m FOLLOWED BY CONDITION 3: Sysmon EventID=1 (Image="*\PsExec.exe" OR "*\powershell.exe") ON Target_Host WITHIN 5m ACTION: Trigger High-Severity Alert + Notify Tier 2!
⚔️ SECTION 4 · ARCHITECTURAL COMPARISON

EDR vs SIEM: Why the SOC Needs Both

A common misconception is that EDR replaces SIEM (or vice versa). In reality, SIEM provides enterprise-wide breadth, while EDR provides deep endpoint surgical control:

Dimension SIEM (Splunk, Sentinel, Wazuh, QRadar) EDR (CrowdStrike, Defender, LimaCharlie)
Visibility Scope Enterprise-Wide (Macro): Firewalls, Cloud, AD, Databases, Web Servers, switches, and endpoints. Endpoint-Specific (Micro): Deep inside Windows/Linux/macOS kernel, processes, RAM, and registry.
Primary Data Normalized event logs, audit trails, NetFlow, and third-party security alerts. Real-time process trees, API/syscall hooks, memory injection telemetry, file hashes.
Active Response Passive analytics engine (relies on SOAR or API integrations to take external action). Direct Live Intervention: Kill processes, quarantine files, and isolate host from network in 1 click!
Retention Long-term compliance & forensic storage (90 days to 7+ years). Short-term operational flight recorder (typically 7 to 30 days).
How They Work Together

The EDR detects suspicious memory behavior on a laptop and forwards the alert to the SIEM. The SIEM correlates that EDR alert with Firewall and Cloud logs to see if the attacker also stole cloud tokens!

🤖 SECTION 4 · AUTOMATION & INTEL

SOAR & Threat Intelligence Platforms (TIP)

To win against automated adversaries, the SOC pairs Threat Intelligence (proactive context) with SOAR (automated response):

Threat Intelligence Platform (TIP) MISP / OpenCTI

Aggregates global adversary intelligence feeds to enrich SIEM logs automatically with known Indicators of Compromise (IOCs):

  • Network IOCs: Malicious C2 IP addresses, botnet domains, Tor exit nodes.
  • Host IOCs: Malware SHA256 file hashes, mutex names, registry paths.
  • Tactical Context: Maps alerts to MITRE ATT&CK techniques and threat actor groups.
SOAR (Orchestration & Automation) Shuffle / XSOAR

Executes automated Playbooks the moment a SIEM alert triggers, slashing Mean Time to Respond (MTTR) from hours to seconds:

  • Auto-Enrichment: Queries VirusTotal, AbuseIPDB, and Whois automatically.
  • Auto-Containment: Instructs the Firewall to block the attacker IP and tells the EDR to isolate the infected host.
  • Ticketing: Opens a pre-populated case in TheHive/Jira and pages the analyst on Slack/Teams.
