# خط أنابيب القياس عن بُعد

> الحالة: تصميم منطقي. يجب اختبار منتجات إعادة التوجيه والمنافذ والتحليل والتوافق بدقة.

| المصدر | الأحداث | الوجهة المنطقية | دليل القبول |
|---|---|---|---|
| Windows مع Sysmon | العمليات والشبكة وتسجيل الدخول والملفات/السجل وفق الإعداد | Splunk عبر مسار جمع Windows مدعوم | حدث اختبار معروف قابل للبحث مع المضيف والوقت الصحيحين |
| pfSense | الجدار الناري وأحداث نظام مختارة | Splunk عبر تسجيل بعيد/مجمّع معد | حدث قاعدة اختبار قابل للبحث ومصنف |
| Suricata في pfSense | التنبيهات وبيانات وصفية مختارة | Splunk عبر تصدير/مجمّع متوافق مع الحزمة | تنبيه اختبار آمن قابل للبحث مع التوقيع والنهايات |
| ويب Ubuntu | سجلات الوصول والأخطاء | Splunk عبر مسار جمع Linux مدعوم | طلب HTTP قابل للبحث مع URI/الحالة/العميل/الوقت |
| Kali | نشاط ترصده الحساسات والأهداف | قياس Suricata أو pfSense أو Windows أو الويب | ظهور الأدلة المتوقعة في المصادر ذات الصلة |

## مبادئ الجمع

- استخدم آليات مدعومة لإصدارات أنظمة التشغيل والمنتجات الدقيقة.
- لا تفترض توفر طريقة إعادة توجيه محددة لـ Suricata EVE في كل إصدار من حزم pfSense.
- أبقِ حركة الجمع ضمن مسارات مسموح بها صراحةً إلى SOC.
- زامن الساعات واحفظ الطوابع الزمنية الأصلية للأحداث.
- وثق الفهرس ونوع المصدر وهوية المضيف والتحليل والاحتفاظ.
- اضبط حجم الأحداث وفق أهداف الدروس.
- لا تودع بيانات اعتماد أو أسراراً مطلقاً.

## الحد الأدنى لاختبارات المصدر

- **Windows:** أنشئ أحداث عملية وشبكة غير ضارة؛ وتحقق من إسناد المضيف والحقول.
- **الويب:** نفّذ طلب HTTP سليماً؛ وتحقق من URI والحالة والعميل والطابع الزمني.
- **pfSense:** أطلق حدث قاعدة جدار ناري معروفة؛ وتحقق من الإجراء والواجهة.
- **Suricata:** استخدم توقيع اختبار آمن وموثقاً؛ وتحقق من إنشاء التنبيه وتسليمه. لا تستخدم برمجيات خبيثة فعلية.

قبل اعتماد كشف على مصدر، وثق الفهرس/نوع المصدر والحقول المتوقعة وعينة منقحة واستعلام البحث والنتيجة المتوقعة والنقاط العمياء. توضع عمليات البحث المشتركة في هندسة الكشف؛ وتبقى عمليات البحث الخاصة بالوحدة معها.
