◆ WHY IT MATTERS

كل شيء في المؤسسة يمر عبر الشبكة

Every device, service, and user in an organization needs to communicate — and that communication happens over the network. It's the shared medium connecting everything together, which makes it one of the most important places to focus security attention.

الخلاصة الأمنية: before diving into specific tools and techniques, it helps to see the bigger picture — the network is the foundation that everything else in this course connects to.

◆ NETWORKING BASICS

البروتوكولات الأساسية: IP و TCP و UDP

Before looking at packet captures, it helps to know the protocols doing the work underneath. IP handles addressing and routing, while TCP and UDP handle getting data to the right application — one favoring reliability, the other favoring speed.

IP — Internet Protocol

Responsible for addressing and routing — getting a packet from source to destination across networks.

IPv4: 32-bit address · version field = 4

IPv6: 128-bit address · version field = 6

TCP — Transmission Control Protocol

Reliable and connection-oriented. Sets up a connection first, then uses sequence numbers to track and reorder every byte sent — so lost data can be detected and retransmitted.

UDP — User Datagram Protocol

Fast and connectionless. No handshake, no delivery guarantee — data is just sent. Ideal when speed matters more than perfection.

لماذا تهمنا هذه الفروقات؟ TCP's handshake confirms both sides are ready before any data flows, and the sequence numbers exchanged during it are what let TCP detect missing or out-of-order segments later on. We'll walk through the handshake in detail shortly.

تشريح ترويسة بروتوكول UDP (بسيطة وخفيفة)

UDP's header is only 8 bytes — no sequence numbers, no handshake fields, nothing tracking reliability. That simplicity is exactly what makes it fast.

Source Port16 bits
Destination Port16 bits
Length16 bits
Checksum16 bits
Source PortPort the datagram was sent from (optional — can be zeroed if no reply is expected).
Destination PortPort the datagram is addressed to on the receiving host.

ChecksumOptional in IPv4 — verifies the datagram wasn't corrupted, but there's no retransmission if it fails.

Compare to TCP: four simple fields versus TCP's sequence numbers, acknowledgments, and flags — the trade-off between UDP's speed and TCP's reliability, in header form.

◆ TCP IN DETAIL

المصافحة الثلاثية لإنشاء اتصال TCP

Before any data is exchanged, the client and server synchronize their sequence numbers through three TCP segments — this is what a SYN scan or a normal connection setup looks like at the packet level.

Reading the numbers: each side's sequence number marks where its byte stream starts, and each ack number confirms "I received everything up to this point, send the next byte." That's the whole trick behind TCP reliability.

◆ PORTS & SERVICES

تقسيم وتصنيف نطاقات منافذ الشبكة (Ports)

A port is a 16-bit number (0–65535) that identifies which application or service on a host a connection belongs to. Combined with an IP address, it forms a full endpoint — e.g. 192.168.1.10:443. Ports are divided into three ranges:

0 – 1023 المنافذ المعروفة (Well-Known Ports) Reserved for standard services (HTTP, DNS, SSH) and assigned by IANA.
1024 – 49151 المنافذ المسجلة (Registered Ports) Registered by vendors for specific applications, less strictly controlled.
49152 – 65535 المنافذ الديناميكية والمؤقتة (Ephemeral) Assigned temporarily by the OS for outgoing client connections.

In practice: a server listens on a well-known port (like 443 for HTTPS), while your browser connects out from a random dynamic port — that pairing is what uniquely identifies the conversation.

◆ DEMO

Handshake with tcpdump

Here's the same three-way handshake as it would appear in tcpdump output — this is exactly what you'll be looking for once we start capturing traffic ourselves.

terminal
$ sudo tcpdump -i eth0 host 93.184.216.34 and port 80 -n 09:14:02.000000 IP 192.168.1.10.51514 > 93.184.216.34.80: Flags [S], seq 1000, win 64240, length 0 09:14:02.028000 IP 93.184.216.34.80 > 192.168.1.10.51514: Flags [S.], seq 5000, ack 1001, win 65535, length 0 09:14:02.028100 IP 192.168.1.10.51514 > 93.184.216.34.80: Flags [.], ack 5001, win 64240, length 0

Reading tcpdump flags: [S] = SYN, [S.] = SYN-ACK, and [.] = an ACK with no other flags set — spotting this three-line pattern is the fastest way to find a handshake in raw output.

◆ CAPTURE APPROACHES

الالتقاط القائم على الحزم الكاملة (Packet Capture)

Packet-based capture records the full contents of every packet — headers and payload — exactly as it crossed the wire. It's the most detailed level of visibility available, since nothing is summarized or thrown away.

EXAMPLE
Capturing every segment of a login attempt with tcpdump — the full handshake, the request, and the response are each stored as individual packets, headers and all.

Advantages

  • Full visibility into headers and payload content
  • تفاصيل جنائية دقيقة للغاية — كل بايت محفوظ وموثق.
  • إمكانية إعادة بناء الأحداث بدقة متناهية (مثل استخراج الملفات المنقولة).

Disadvantages

  • استهلاك هائل لمساحات التخزين في الشبكات النشطة.
  • يتطلب قدرات معالجة عالية عند التحليل على نطاق واسع.
  • حركة المرور المشفرة (TLS) تخفي محتوى الحمولة حتى مع التقاطها.
◆ CAPTURE APPROACHES

الالتقاط القائم على التدفقات (NetFlow / IPFIX)

Flow-based capture summarizes an entire conversation between two endpoints into a single record — source/destination IP and port, protocol, packet count, byte count, and duration — instead of storing every packet. Common implementations include NetFlow, IPFIX, and sFlow.

EXAMPLE
src=192.168.1.10:51514   dst=93.184.216.34:80   proto=TCP
packets=142   bytes=98,304   duration=4.2s
One record for the entire session — not the individual SYN, SYN-ACK, or ACK packets.

Advantages

  • مساحة تخزين أصغر بكثير مقارنة بالالتقاط الكامل للحزم.
  • قابل للتطبيق والتوسع بسهولة في شبكات الشركات العملاقة.
  • ممتاز لرصد الأنماط الشاذة — أحجام النقل الضخمة والاتصال المتكرر (Beaconing).

Disadvantages

  • لا يوفر رؤية لحمولة البيانات — لا يمكن رؤية محتوى ما تم نقله.
  • لا يمكن إعادة بناء الأحداث التفصيلية على مستوى الحزم الفردية.
  • لا يكشف التهديدات الخفية المعتمدة على محتوى الحمولة.
◆ منهجيات التحليل

التحليل اللحظي المباشر في الوقت الفعلي (Online)

Online analysis (also called live or real-time analysis) inspects traffic as it crosses the network, without necessarily saving it first. This is how tools that need to react immediately — like an IDS/IPS or a live monitoring dashboard — actually work.

EXAMPLE
Running tcpdump -i eth0 and watching packets print to the screen live, or an IDS evaluating every connection attempt the moment it happens and firing an alert instantly.

Advantages

  • اكتشاف وتنبيه فوري لحظة وقوع الحدث الأمني.
  • يمكّن من اتخاذ إجراء فوري — مثل قطع اتصال الهجوم الجاري.
  • لا يشترط حفظ مساحات تخزين هائلة لمراجعة البيانات لاحقاً.

Disadvantages

  • وقت المعالجة المتاح لكل حزمة محدود جداً لتجنب تأخير الشبكة.
  • قد يعاني من صعوبة مواكبة السرعات الفائقة في الشبكات الضخمة.
  • يصعب عليه رصد الأنماط المعقدة البطيئة التي تتضح عبر فترات زمنية طويلة.
◆ منهجيات التحليل

التحليل اللاحق المسترجع (Offline / Retrospective)

Offline analysis (also called retrospective analysis) captures traffic to a file first and reviews it afterward, with no time pressure. This is the typical incident-response workflow when digging into what really happened.

EXAMPLE
Running tcpdump -w capture.pcap during an incident, then opening that file in Wireshark hours or days later to trace exactly what happened, packet by packet.

Advantages

  • لا يوجد ضغط وقت — يمكن إعادة تشغيل الحزم ومراجعتها مراراً وتكراراً.
  • يدعم التحقيقات الجنائية العميقة والمفصلة لجميع الأدلة.
  • إمكانية ربط الأحداث ببعضها عبر فترات زمنية متباعدة.

Disadvantages

  • يتطلب توفير مساحات تخزين كافية لملفات الالتقاط المحفوظة.
  • الكشف يكون متأخراً بعد وقوع الحادثة بالفعل.
  • لا يمنع الهجوم اللحظي أثناء حدوثه على أرض الواقع.
◆ الأدوات التطبيقية

مقدمة إلى أداة التقاط الحزم tcpdump

tcpdump is a command-line, packet-based capture tool built on libpcap. It's available on nearly every Linux/Unix system, making it one of the fastest ways to capture and inspect traffic without installing anything extra.

basic syntax
$ sudo tcpdump -i eth0 -n port 443 # -i eth0 → capture on interface eth0 # -n → don't resolve hostnames (faster, cleaner output) # port 443 → only show traffic on port 443
-iInterface to capture on, e.g. eth0.
-nSkip DNS/hostname resolution for faster output.
-cStop after capturing a set number of packets.
-wWrite captured packets to a file for later analysis.
-rRead and display packets from a saved capture file.
-v / -vvIncrease output verbosity for more packet detail.
host / portFilter traffic to a specific IP address or port.
and / orCombine multiple filters, e.g. host X and port 80.

◆ الأدوات التطبيقية

فلاتر الالتقاط في tcpdump بصيغة BPF

Raw traffic is noisy — capture filters use Berkeley Packet Filter (BPF) syntax to narrow tcpdump down to exactly the traffic you care about.

example filter
$ sudo tcpdump -i eth0 src 192.168.1.10 and dst port 443 and tcp # only TCP traffic, from 192.168.1.10, headed to port 443

كلمات الفلترة الأساسية

host <ip>Match traffic to or from a specific address.
src <ip>Match traffic only from a specific source address.
dst <ip>Match traffic only to a specific destination address.
port <num>Match traffic on a given port, in either direction.
src port / dst portNarrow a port filter to just the source or destination side.
net <subnet>Match traffic within a network, e.g. net 192.168.1.0/24.

بروتوكولات الفلترة

tcpOnly TCP traffic — connections, handshakes, most application traffic.
udpOnly UDP traffic — DNS, streaming, VoIP, and similar.
icmpOnly ICMP traffic — pings and network diagnostic messages.
arpOnly ARP traffic — local address resolution requests and replies.

أدوات دمج الفلاتر المركبة

andيجب تحقق كلا الشرطين معاً (AND), e.g. host X and port 80.
orEither condition may match, e.g. port 80 or port 443.
notExcludes traffic matching a condition, e.g. not port 22.
