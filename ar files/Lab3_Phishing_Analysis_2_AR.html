◆ METHOD DEEP DIVE

مسار عمل المحلل في فحص الروابط (URL Analysis)

بعد فهم بنية الرابط، يتعامل المحلل مع الروابط المشبوهة عبر ثلاث مراحل منظمة — الاستخراج، الفحص، ثم الفحص بالأدوات:

1

1. الاستخراج (Extract) the URL

  • استخراج كل رابط من ترويسة الرسالة ومحتواها.
2

Check for Red Flags

  • البحث عن محاولات الانتحال — النطاقات الشبيهة (Typosquatting) وسوء استخدام الـ Subdomains.
  • الحذر من خدمات تقصير الروابط (bit.ly وغيرها) التي تخفي الوجهة الحقيقية.
  • الانتباه لتقنيات التشفير والترميز (Hex, URL Encoding, IP formats) لإخفاء الرابط.
3

3. الفحص بالأدوات (Scan) With Tools

  • Submit the URL in its original form — scanning tools need the real link, not a defanged one
  • Cross-reference results to reach a verdict

قاعدة ذهبية: إياك أن تفتح أو تزور رابطاً مشبوهاً من متصفحك مباشرة! Always use an isolated analysis VM, a dedicated sandbox tool, or a URL-scanning service.

نصيحة للمحلل: A "clean" result from one tool is not proof of safety — brand-new malicious domains are often not yet indexed anywhere. Cross-reference at least two independent sources before clearing a URL.

◆ METHOD DEEP DIVE

تحليل المرفقات — التحليل الثابت مقابل الديناميكي

Once an attachment is securely extracted, hash it and search that hash's reputation first — a known-bad hit alone can be enough for a verdict. From there, an analyst has two complementary approaches to dig deeper.

التحليل الثابت (Static Analysis)

  • Examines the file without running it
  • Safe, fast, and repeatable at scale
  • PDF: pdfid / pdf-parser to pull out embedded الروابط (URLs) and objects
  • Office doc: oledump to find and extract macros

التحليل الديناميكي (Dynamic Analysis)

  • Executes the file in an isolated sandbox
  • Reveals real runtime behavior and intent
  • Process, file system, registry, network activity
  • Slower, and some malware detects and evades sandboxes

Scope note: Full malware analysis process is outside this course. The goal here is triage — pull out embedded الروابط (URLs), objects, and macros to confirm intent, or hand the file to a sandbox and read its report.

◆ STATIC ANALYSIS

التحليل الثابت (Static Analysis) Techniques

Start every file the same way — hash it and search that hash's reputation. If it comes back unknown, the next tools depend on the file type.

Hash & Search: Compute the file's MD5 / SHA-1 / SHA-256 and search it on VirusTotal and other reputation sources — the fastest check, and often enough to reach a verdict on its own.

PDF Files

1

pdfid

  • Quick triage count of risky keywords — JavaScript, embedded files, launch actions
2

pdf-parser

  • Digs into the flagged objects to pull out embedded الروابط (URLs) and payloads

Office Documents

1

oledump

  • 2. الفحص البصري (Inspect)s the OLE structure of Word/Excel files to detect embedded VBA macros
2

1. الاستخراج (Extract) & Review

  • Pull out the macro code and read it without ever letting it run

Scope note: The goal is triage, not full reverse engineering — extract the indicator (a URL, an object, a macro), then decide whether it's worth escalating to a sandbox.

◆ DYNAMIC ANALYSIS

التحليل الديناميكي (Dynamic Analysis) & Sandboxing

The file is detonated inside an isolated, monitored environment — an analyst watches what it actually does, rather than guessing from its code alone.

Process Behavior

Which child processes spawn, what commands run, and whether the sample tries to inject into or hollow out other processes.

File System & Registry Changes

New or modified files, dropped payloads, and registry keys added for persistence across reboots.

Network Traffic

Command-and-control callbacks, DNS requests, and any second-stage payload downloads captured with full packet detail.

Sandbox-Evasion Checks

Some malware detects it's being watched — checking for a mouse, a real user, or specific VM artifacts — and stays dormant to avoid analysis.

SANDBOX

Any.Run

Interactive, browser-based sandbox with live process, network, and screen visibility during detonation.

SANDBOX

Joe Sandbox

Deep behavioral reports covering process trees, network activity, and MITRE ATT&CK technique mapping.

SANDBOX

Hybrid Analysis / Cuckoo

Free and open-source options for automated detonation with detailed behavioral reports.

◆ TOOLING

منصات وأدوات التحليل المؤتمتة والشاملة

Manual analysis doesn't scale to hundreds of reported emails a day — these two tools automate the repetitive parts of the process.

SCRIPT

eioc.py

Parses a raw email file and extracts every IOC in one pass — sender and reply-to addresses, الروابط (URLs), IPs, and attachment hashes — turning what would be several manual steps into a single command.

WEBSITE

PhishTool

A web-based triage platform — upload the email and it pulls header, URL, and attachment analysis into one case, with a verdict and case management built in.

نصيحة للمحلل: Automation accelerates triage but doesn't replace judgment — a tool's verdict is one input into the analyst's own conclusion, not a substitute for it.

◆ METHOD DEEP DIVE

إجراءات الدفاع — التفاعلية مقابل الاستباقية

Once a phishing email is confirmed malicious, the response splits into two tracks: contain what already happened, and reduce the chance it happens again.

الدفاع التفاعلي (Reactive Defense)

  • Taken after a confirmed threat is found
  • Focused on containment and eradication
  • Time-sensitive — every minute counts
  • e.g. blocking, quarantining, resetting credentials

الدفاع الاستباقي (Proactive Defense)

  • Put in place before an attack occurs
  • Focused on reducing likelihood and blast radius
  • Ongoing, not tied to a single incident
  • e.g. سياسة DMARC وتطبيق وضع الرفض (Reject) enforcement, training, threat intel

نصيحة للمحلل: A mature security program treats every reactive response as an input to the proactive program — each incident should improve the defenses that prevent the next one.

◆ REACTIVE DEFENSE

مراحل الدفاع التفاعلي عند اكتشاف الحادثة

بمجرد تأكيد هجوم التصيد، تتحرك الاستجابة عبر خمس مراحل متتالية — من وقف الانتشار وحتى تدريب المستخدمين:

1

1. الاحتواء (Containment)

  • تحديد نطاق الحادثة والأجهزة المتأثرة
  • حجر الرسائل وسحبها فوراً
  • حظر مؤشرات المرسل (Sender Artifacts)
  • حظر مؤشرات الروابط (Web Artifacts)
  • حظر مؤشرات الملفات (File Hashes)
2

2. الاستئصال (Eradication)

  • Remove malicious emails
    • البحث الموسع في البريد عبر eDiscovery
  • حذف كافة الملفات المترسبة في الأجهزة
  • تقديم بلاغات إساءة الاستخدام لمزودي الخدمة
  • تغيير فوري لكلمات المرور وتصفير الجلسات
  • إعادة تهيئة الأجهزة المصابة إن لزم الأمر
3

3. التعافي (Recovery)

  • استعادة الأنظمة والخدمات للعمل الطبيعي وتأكيد سلامتها
4

4. التواصل (Communication)

  • إشعار المستخدمين المتأثرين وتوجيههم
  • إحاطة الإدارة وفرق العمل المعنية بمجريات الحادثة
5

5. التوعية (Education)

  • تقديم تدريب توعوي فوري مخصص للمستخدم المستهدف لمنع التكرار
◆ PROACTIVE DEFENSE

تدابير الدفاع الاستباقي لحماية المؤسسة

ضوابط دفاعية دائمة تُدار باستمرار عبر خمس طبقات متكاملة لتقليل احتمالية وتأثير هجمات التصيد القادمة:

1

1. تصفية البريد (Filtering)

  • بوابات أمن البريد المتطورة (SEG)
  • وضع علامة تنبيهية على الرسائل الخارجية
2

URL 3. الفحص بالأدوات (Scan)ning & Blocking

  • فحص الروابط في الوقت الفعلي عند النقر
  • حظر النطاقات حديثة التسجيل (NRDs) تلقائياً
3

3. تصفية المرفقات

  • حظر الامتدادات الخطرة (.exe, .iso, .scr, .vbs)
  • فحص المرفقات في بيئة Sandbox قبل التسليم
4

Email 4. المصادقة (Auth) Methods

  • سجل SPF (التحقق من خوادم الإرسال المصرحة)
  • توقيع DKIM التشفيري للرسائل
  • سياسة DMARC وتطبيق وضع الرفض (Reject)
5

5. تدريب المستخدمين

  • برامج التوعية الأمنية المستمرة
  • تجارب محاكاة تصيد دورية وعملية
  • توفير زر إبلاغ سريع عن الإيميلات المشبوهة

نصيحة للمحلل: No single layer is enough on its own — these five work together, so a phish that slips past filtering can still be stopped by authentication checks, sandboxing, or a trained user reporting it.

◆ METHOD DEEP DIVE

التوثيق وكتابة التقارير الأمنية (Reporting)

لا تُغلق أي حادثة أمنية حتى يتم توثيقها رسمياً — التقرير يحول الاستجابة الفردية إلى معرفة مؤسسية يستفيد منها الفريق بأكمله:

الذاكرة المؤسسية (Institutional Memory)

قد يتعامل محلل آخر مع هجوم مماثل غداً. التقرير الممتاز يمكّنه من التعرف على الهجوم وربطه فوراً.

Compliance & Accountability

جهات التدقيق، شركات التأمين السيبراني، والهيئات التنظيمية تتطلب إثباتات رسمية لما تم اكتشافه وكيف تم التعامل معه.

Metrics & Trends

تراكم التقارير يوضح الإدارات الأكثر استهدافاً، ويقيس مدى فاعلية برامج التدريب والتوعية.

Handoff & Escalation

يتيح التقرير الواضح تسليم الحادثة لفرق أخرى (مثل الـ IR أو الهندسة) أو للإدارة دون الحاجة لإعادة الشرح الشفهي.

Justify the Response

نصيحة ذهبية: لا تكتفِ بسرد ما فعلته فقط — بل اشرح "لماذا" فعلته. وضّح المنطق الأمني وراء كل قرار، ليفهم كل من يقرأ التقرير أسباب الإجراء وليس نتيجته فقط.

نصيحة للمحلل: Write for a reader who knows nothing about this incident — spell out acronyms, give a clear timeline, and don't rely on memory only you have.

◆ REPORT TEMPLATE

الهيكل النموذجي لتقرير حادثة التصيد

التنسيق المنظم والموحد يجعل قراءة التقرير سريعة تحت ضغط العمل، ويسهل مقارنته بالحوادث السابقة:

1

الوصف العام (Description)

  • ملخص بلغة واضحة ومباشرة لما يحتويه الإيميل وسبب الاشتباه به.
2

الترويسات (Headers)

  • التاريخ، الموضوع، المرسل، المرسل إليه، مسار الرد، عنوان IP للمرسل، ومعرف الرسالة.
3

الروابط (URLs)

  • حصر وتوثيق كل رابط تم استخراجه من ترويسة ومحتوى الرسالة.
4

المرفقات (Attachments)

  • اسم كل مرفق، وقيم الهاش التشفيرية له (MD5, SHA1, SHA256).
5

تحليل المؤشرات (Artifact Analysis)

  • نتائج الفحص التفصيلية لكل من: فحص المرسل، فحص الروابط، وفحص المرفقات.
6

الحكم والتصنيف (Verdict)

  • التصنيف النهائي القاطع للحادثة — خبيث (Malicious)، مشبوه (Suspicious)، أو سليم (Benign).
7

إجراءات الدفاع المتخذة (Actions Taken)

  • توثيق كافة الخطوات والإجراءات التفاعلية التي تم تنفيذها لاحتواء التهديد.

أفضل الممارسات (Defanging): Defang every URL and IP written into the report — hxxp[://]evil[.]com, 1.2.3[.]4 — so nothing in the document is clickable or gets auto-parsed as a live indicator by whoever reads it next.
